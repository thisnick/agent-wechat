# Interface listings

These files list every public interface of agent-wechat, one item per line, generated from the code. CI fails when a listing no longer matches the code, so every interface change shows up here as a diff. A PR that changes any listing needs the owner's approval before it merges.

| File | Interface | Generated by |
| --- | --- | --- |
| `cli/wx.txt` | Every `wx` command, argument, flag and alias, including hidden ones | `packages/native-client-rust/crates/wx/src/cli_interface_tests.rs` |
| `crates/<crate>.txt` | The public API of each library published to crates.io, with default features on Linux x64 | `scripts/interfaces/rust-crates.mjs` |
| `openclaw/tools.txt` | OpenClaw agent tools and their parameters, trusted tool policies and gateway HTTP routes | `packages/openclaw-extension/scripts/interface-listing.mjs` |
| `openclaw/config.txt` | OpenClaw plugin and channel configuration keys | `packages/openclaw-extension/scripts/interface-listing.mjs` |

The daemon's HTTP API and the desktop/web UI aren't listed yet. Their request and response types are checked separately by `scripts/native-generate-types.sh --check`.

## Update the listings

After changing the CLI, a published crate or the OpenClaw plugin:

```bash
pnpm install
pnpm interfaces          # rewrite every listing
git diff interfaces/     # review what changed
```

`pnpm interfaces --check` fails instead of writing. It needs the pinned Rust toolchain, `cmake` and Node. The CLI listing is also checked by `cargo test`.

## Format

Each row is `ITEM | ATTRIBUTES | DOC`, sorted by `ITEM`, and `ITEM` is unique within a file. `DOC` is the item's help text, doc comment summary or description; `MISSING HELP`, `MISSING DOC` or `MISSING DESCRIPTION` marks a gap.

```text
wx messages send --video-quality | takes <VIDEO_QUALITY>, values normal|original | Prepare normal playback, or include the unchanged original video too
fn wechat_calls::mixer::PcmMixer::remove_track | fn(&mut self, track_id: u32) -> bool | MISSING DOC
tool wechat_history.limit | integer, min 1, max 50, default 20 | Maximum number of results on this page.
```

- **CLI attributes:** `position N`, `required`, `takes <VALUE>`, `switch`, `count`, `repeatable`, `short -x`, `alias --name`, `default X`, `values a|b`, `global`, `hidden`. Global flags are listed once, on `wx`.
- **Crate rows:** the item kind and path, then its signature. `impl Trait for Type` rows list explicit and derived trait implementations; automatic traits such as `Send` are left out. `#[cfg(...)]` marks platform-specific items.
- **OpenClaw rows:** `tool NAME` and `tool NAME.param`, `plugin.key` and `channel ID.key`, with JSON-schema type, `required`, allowed values, limits and defaults. `enabled by default` or `optional` says whether an agent gets a tool without allowing it.

## Checks on every PR

| Check | Fails when |
| --- | --- |
| Interfaces up to date | A generator's output differs from the committed listing |
| Interface docs | A row added or changed in this PR says `MISSING …`. Gaps from before a listing existed stay allowed until someone fixes them |
| Interface approval | The PR changes `interfaces/` and the `interfaces-approved` label doesn't cover the current listings |

A bot comment on the PR lists the added, changed and removed rows and flags breaking changes:

- **CLI:** a removed command, flag or alias; a new required argument on an existing command; a removed short flag or alias; a changed default or position; removed allowed values; a flag that changes between switch and value.
- **Crates:** a removed item or changed signature; a new field on a struct with public fields; a new variant on an exhaustive enum; a new required trait method.
- **OpenClaw:** a removed tool, parameter or key; a newly required parameter; a narrowed type, range or allowed values; a changed default; a tool that is no longer enabled by default.

It also warns when a changed listing has no changeset for its package, or a breaking change has a changeset below `major`.

## Approval

The owner approves by adding the `interfaces-approved` label to the PR. The check records the listings' tree hash at that moment. A later push that changes the listings removes the label and asks again; other pushes keep the approval.

Coding agents never add this label themselves and never merge a PR while **Interface approval** is pending or failing.
