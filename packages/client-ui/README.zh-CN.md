# 浏览器连接预览 (Connected browser preview)

[English](README.md) | [简体中文](README.zh-CN.md)

`pnpm client:dev` 会启动共享的 React 客户端、其真实内置的 Rust Hub 以及本地虚拟上游。在此过程中不会读取生产环境端点、CLI 配置或官方 Profile。这是一个开发预览环境，而非打包后的桌面客户端。

## 启动

请先安装 `AGENTS.md` 中指定的开发前置条件，然后执行：

```sh
pnpm install --frozen-lockfile
pnpm client:dev
```

该命令会使用优化后的测试 Profile 构建 `wx-dev` 并打印本地浏览器访问 URL。添加一个账号，选择 **“模拟扫码” (Simulate scan)**，然后选择 **“模拟手机确认” (Simulate phone approval)**。UI 将轮询真实的登录操作并自动打开聊天会话。常规的二维码登录同样只需要手机端确认。Hub 会根据其受限刷新策略自动更新未扫描的二维码。视图会读取登录操作的二维码代际与过期时间戳，并在代际发生变化时拉取新的 PNG 图片。模拟器 PNG 图片编码的是有效的虚拟 `agentwechat-simulator:login:…` 负载，绝非官方登录 URL。

模拟器为每个二维码提供 120 秒有效期。原生协议目前在本地设置了 240 秒的二维码过期时间，这并非从服务响应中解码得出的过期时间戳。UI 使用 Hub 的 `expiresAt` 显示 **“验证码在 … 后刷新”**，并在 9 分钟的登录有效期内最多发起三次自动更新。扫码后，手机确认挑战拥有独立的截止期限。在**“模拟器测试控制” (Simulator test controls)** 下的 **“模拟验证码过期” (Simulate code expiry)** 可以提前演练刷新；常规过期无需按键操作。

页面刷新后重新打开同一账号会恢复其已保存的登录操作，包括已在手机上扫码的状态。浏览器标签页仅存储登录请求密钥和操作 ID，范围限定在当前 Hub 的服务器 ID 和账号下。丢失的登录响应会使用相同的密钥重试。临时查找错误不会开启第二次登录；已结束的挑战可以开启新的尝试。

在两个浏览器标签页中打开该 URL 并选择相同账号。使用**“模拟器控制” (Simulator controls)** 注入传入文本、手机发起的自身发送、传入的图片/文件/视频/语音或动态表情、不可用图片、服务端拒绝或丢失的发送确认。控制器会改变虚拟上游状态；消息将通过实际 Hub 的同步/存储/事件流水线传递，不会生成自动伪造回复。

文本发送请求每次使用一个稳定的密钥。排队中、被拒绝和 `needs_review`（待审核）的回执保持各自独立。点击 **“检查状态” (Check status)** 将读取回执，绝不重复发送。已被接受的历史记录将从 Hub 中拉取。事件流从上次处理的游标处恢复；过期的游标会在继续前重新构建视图。账号与会话的代际标识可防范迟到的请求冲突。

在会话中点击 **“在会话中查找” (Find in conversation)** 可搜索 Hub 上存储的该会话历史记录，包括浏览器当前已加载页面之外的消息。**“加载更多匹配项” (Load more matches)** 使用 Hub 的游标继续同一查询。清空查询可恢复聊天视图；切换账号或会话将丢弃所有迟到的搜索响应。

将鼠标悬停在会话上或使其获得焦点可显示 **“置顶/取消置顶” (Pin/Unpin)** 和 **“静音/取消静音” (Mute/Unmute)** 按钮。未读角标保持可见；悬停面板会显示已加载清单中的聊天信息。在触摸屏上，这两项操作均保持可见。右键点击也会呼出菜单。置顶和静音开关也可在“会话详情”中操作。置顶聊天始终集中在顶部。置顶操作在保存时会立即更新图标、开关和列表分区，随后采用 Hub 确认的顺序。被拒绝或不确定的更改会回退到上一次确认的状态并保留其恢复回执。这两个控件共享一个挂起的操作；置顶未打开的聊天不会打开该聊天，也不会清除其未读角标。未知的置顶状态可以手动刷新。**“检查状态”** 可在不重新发送的情况下恢复不确定的更改（包括在页面刷新后）。Hub 必须声明该聊天类型支持置顶，且连接密钥必须具备账号管理权限。“文件传输助手”及其他不支持的内置聊天无法置顶。

Hub 访问密钥保存在内存中。IndexedDB 保存近期历史记录、联系人、经校验的媒体字节、头像、草稿以及挂起操作的回执。每条记录的范围限定在 Hub 地址、其持久化服务器 ID 以及账号。ID 和游标保持为字符串格式，包括 64 位的服务器 ID。挂起的发送在页面刷新后通过回执进行检查，绝不自动重发。少量用户偏好、上次使用的账号、会话及滚动锚点保存在 LocalStorage 中。

返回有效的 Web 会话将自动打开上次登录的账号与会话。在恢复其缓存前会向 Hub 校验认证状态。登出操作会隐藏已缓存的历史记录，但仍在此设备上为该账号的下次登录保留数据。删除 Profile 和 **“清除临时数据” (Clear temporary data)** 会移除已拉取的数据。在事件追赶后，最后一条消息 ID 未发生变化的会话可以直接复用已缓存的历史记录。发生变化或不可用的 ID 将触发重新读取历史。凭证不会复制到任何浏览器存储中。**“设置 → 在此设备上” (Settings → On this device)** 会显示使用情况并清理拉取的数据，同时保留草稿和挂起的回执。打开已缓存的会话在 5 分钟后会重新检查其历史，即使事件流当前处于连接状态也是如此。只有成功的最新历史拉取才会刷新该计时；事件重放、打开会话和加载更早页面则不会。可见附件共享批量元数据读取，将已连接的应用重新切回焦点时不会重新加载每一个会话。如果本地存储不可用，客户端将继续依靠内存和标签页存储工作。引导密钥私密保存在模拟器工作区内，因此已命名的预览环境可以在重启时不使预览链接失效。

按下 Ctrl+C 仅停止由此命令创建的子进程并清理一次性状态。如需保留命名的虚拟工作区：

```sh
pnpm client:dev --data-dir /path/to/new-simulator-data
```

对于测试，环境变量 `WX_DEV_BINARY` 可指定已构建好的 `wx-dev`。`CLIENT_UI_PORT` 可指定本地 Vite 端口。`CLIENT_UI_ORIGIN` 可声明 HTTPS 反向代理来源。它会修改预览环境允许的主机/来源及浏览器连接，但不会连接到另一个 Hub。代理应始终保持在可信网络内部。若 Hub 的身份不是 `simulator`，启动器将拒绝启动。

若需将预览界面连接到现有的原生守护进程，请使用独立的启动器明确指定：

```bash
pnpm --filter @agent-wechat/client-ui connect \
  --server http://127.0.0.1:6174 \
  --account ACCOUNT_ID \
  --token-file /absolute/private/browser-token \
  --state-dir /absolute/private/browser-preview
```

请使用仅所有者可读的文件来存放现有的守护进程连接密钥。密钥保留在启动器中，浏览器使用私有的预览密钥。启动器在监听前会检查原生守护进程的身份。`--account` 可选地校验初始账号是否存在，但并不限制 Profile 管理。账号创建、登录、登出和确认删除均使用标准的账号 API。守护进程原有的 Token 校验依然有效；不会引入任何前端专属角色或特殊管理模式。Token 和守护进程管理路由仍会被代理拦截。

启动器支持 `CLIENT_UI_PORT` 与 HTTPS `CLIENT_UI_ORIGIN`。请对终端打印的带有 Fragment 的链接严格保密。关闭启动器不会影响外部守护进程的继续运行。`node scripts/client-ui-connect-smoke.mjs` 会使用本地 HTTP 固件检查代理功能。

若要连接多个 Hub，可以使用 `--connections-file /absolute/private/connections.json` 替代 `--server` 和 `--token-file`。请将该 JSON 文件保持为仅所有者可读：

```json
[
  { "id": "local", "name": "Local hub", "server": "http://127.0.0.1:6174", "tokenFile": "/private/local-key" },
  { "id": "test", "name": "Test hub", "server": "http://127.0.0.1:6176", "tokenFile": "/private/test-key" }
]
```

可选的 `endpoint` 提供了 Hub 的公共源地址用于展示及浏览器存储；实际请求仍使用其配置的内部 `server`。连接界面会展示每个命名的 Hub 并记住上次成功的选择。某个 Hub 离线不会阻止打开另一个。每个 Hub 都有独立的代理路由和守护进程密钥；私有的预览密钥可授权访问所有已配置的 Hub。浏览器请求始终停留在预览源上，无需在 Hub 端修改 CORS。请将此本地连接文件及所有密钥保存在仓库外部。

**“管理账号” (Manage accounts)** 会打开账号选择器，每个 Profile 都带有一个设置按钮。已登出的 Profile 可以重新登录或被删除。删除操作需要输入 Profile 的当前名称，并发送其规范 ID 作为确认。后端会拒绝正在进行的活跃任务和已登录的 Profile，取消注册该 Profile，并保留所有本地文件和恢复记录。已删除的 ID 和 Profile 路径保持保留状态；这不是从磁盘彻底删除微信数据，也不是一键还原功能。

模拟器启动器每秒推进一次时钟，使得二维码过期与刷新自然发生。独立的模拟器保留了受控的虚拟时钟以支持可重复的回归测试。

## 认证与限制

打印出的 URL 在其 Hash 片段中携带了一个随机生成的预览引导秘钥。浏览器会立即将其移除，并为开发端点换取一个 HttpOnly、SameSite 的 Cookie。该 Cookie 有效期为 30 天，并在连接恢复时自动续期；手动输入预览访问密钥也可以建立相同的 Cookie。主机/来源检查及该秘钥/Cookie 可保护引导流程与模拟器控制端。独立的模拟器控制令牌始终保留在启动器中。Hash 片段中的秘钥与访问密钥切勿提交进版本库。

Vite 负责提供开发静态资源并代理现有 API，不存在第二个业务后端。生产环境静态托管、绑定的桌面 Hub、Agent 配置以及 Tauri 打包属于后续跟进工作。连接表单使用现有的 Bearer SDK，要求使用 HTTPS 或环回 HTTP；跨源远程 Hub 还需要经批准的浏览器 CORS 配置。当将此预览环境连接到显式选定的原生守护进程时，建议使用上述同源代理模式。

## 附件与表情

消息输入框在聚焦或点击时，会根据当前显示的已读状态版本清除所选聊天会话的未读计数。并发的聚焦与回复操作共享单次请求，发生冲突时绝不会自动清除新收到的消息。

回复消息会在输入内容上方显示发送者以及从 `message.quote` 中提取的内嵌摘录。渲染文本或链接引用不会发起引用解析请求，也绝不会替换已存储的原始内容。图片引用使用父回复的媒体标识展示一个标准的缩略预览。已撤回或不可用的引用会保留简短的状态标签。转发的历史消息将渲染标准化文本。未知消息类型会显示不支持内容的标签，而不会进入媒体处理流。

图片和表情会直接展示其内容，不附带文件头或状态文字。气泡旁的时间戳及右上方的消息操作栏在鼠标悬停或键盘聚焦时出现。自己发送的消息没有发送者标签；接收到的消息保留发送者昵称。时间戳位于已发气泡左侧和已收气泡右侧。触摸设备可正常呼出这些操作。菜单提供复制文本或打开照片的选项；自己的消息还会提供带有独特删除图标的 **“撤回” (Recall)** 选项。点击后会弹出确认对话框并显示所选消息；取消或按 Escape 键不会发送任何请求。撤回操作会在页面刷新后保持其准入密钥和操作回执。对于未知结果，界面提供状态检查选项，而非发起另一次尝试。具体某条消息是否可以撤回由 Hub 判定。已撤回的气泡根据 API 派生的原发送者和方向进行定位。缺失发送者或方向会生成不带头像的中性提示。提示文字取自 `recall.replacementText`，默认回退至 **“消息已撤回”**；UI 不会从原作者、控制发送者或提示文本中推断撤回发起人。侧边栏使用相同的提示。合并后的原生撤回实现负责作者恢复、提示存储和搜索清理；浏览器端不添加作者账本。

**“回复” (Reply)** 操作会为文本编辑器选择一条受支持的消息。其预览可以跳转至原消息，也可以在不丢失草稿的情况下关闭。文本与引用选择均限定在每个账号与聊天范围内。发送时仅将存储的消息 ID 和精确的服务器 ID 传递给原生引用文本 API。排队中和不确定的发送保留该引用；检查状态不会提交另一次发送。已知已撤回或发生更改的原消息会阻止发送，直到移除或替换该引用。发送附件需要先取消已选中的文本回复。模拟器测试了相同的守护进程准入、投影、事件流及内嵌引用契约；官方端点验收与接收方渲染仍需作为独立的最终检查。

守护进程在收到图片/视频缩略图和语音留言时会自动下载，独立于浏览器。其他已声明的图片、视频、文件和表情变体遵循账号的自动下载限制（默认 50 MB）。未知大小和更大的版本仍需手动下载。**“设置 → 自动下载” (Settings → Automatic downloads)** 会通过与 `wx account settings` 相同的 API 更新 Hub 的账号注册表；它不会更改官方 Profile 或浏览器独立的临时存储配额。传入的图片在允许的标准版本下载过程中会先展示缩略图，校验通过后切换为标准画质。点击照片或视频会打开一个共享查看器，带有上一个/下一个控件、缩略图栏以及 **“定位到消息” (Show message)**。图片在固定导航箭头和缩略图栏后方的全屏画布上进行缩放和平移。动画缩放、拖拽平移、滚轮和双指缩放采用 `react-zoom-pan-pinch`；**“重置缩放” (Reset zoom)** 可恢复到居中适应视图。单击图片可切换缩放；拖拽可进行平移而不触发切换。在图片画布上按 Enter 或空格键同样可切换缩放，`+`、`-` 和 `0` 对应放大、缩小和重置。开启“减弱动态效果”偏好将禁用缩放动画和平移惯性。视频带有原生播放控件。视频缩略图与视频播放独立加载，因此浏览缩略栏不会拉取完整视频。更早的照片和视频可根据需要通过会话的历史游标加载。查看器在 **“查看原图/原文件” (Get original)** 及其传输进度旁始终保留 **“下载” (Download)** 按钮。**“查看原文件”** 先显示云下载图标，随后显示加载图标与 **“正在获取原文件…”**。其进度附带 **“取消”** 文字操作；关闭图标可退出查看器。一旦原文件完成缓存，**“下载”** 将该原文件保存至本地设备。画质与大小仅在悬停或聚焦下载控件时显示为“压缩”或“原文件”。若未提供原图来源，则仅能下载标准画质；下载提示栏会对此进行说明。传输进度和取消按钮在下载运行期间可见。即使原图下载完毕，聊天会话中仍继续展示标准画质。轮播栏首先展示标准画质，在原图字节加载并解码后替换为经校验的缓存原图。画质提升失败时仍保持显示标准画质。打开轮播栏不会主动向微信请求原图。不可用的图片将显示对应图标。

在触摸屏上，在适应屏幕尺寸下左右滑动可在各项目间切换。放大后的图片保留其平移与双指手势；视频控件保留原生触摸行为。

分享的链接在消息声明缩略图时会展示附带缩略图的卡片。缩略图下载采用与聊天图片相同的校验媒体流程和设备存储；无缩略图的卡片展示链接图标。

聊天消息、主查看器及其缩略图栏共享统一的预览缓存。针对相同账号、资产、画质和来源哈希的请求将进行去重。空闲预览在 64 MiB / 128 项的配额内保留；可见预览保持固定直到其使用者关闭。重新打开聊天或查看器可立即复用保留的 Blob URL。撤回操作会使该消息的预览项失效，登出或断开连接会清除相应账号或连接的缓存。经过验证的预览字节还可在 IndexedDB 中跨刷新保存，共享与头像通用的 256 MiB LRU 空间。在复用相同账号、消息、画质和内容哈希的字节前，客户端会先从 Hub 读取最新的资产元数据。Blob URL 和临时内容 URL 不会持久化存储。

文件显示其文件名和常显的下载控件。**“获取原文件”** 使得原文件可供下载，随后的 **“下载”** 操作将其保存至设备。常规文件（包括 PDF）不会渲染图片占位符或内嵌 PDF 查看器。

点击引用可在相同账号和会话中查找其服务器 ID，仅在需要时加载更早的历史页面，随后滚动至其原消息处。这种跳转导航不会修改显示的内嵌摘录。缺失或已撤回的原消息保持其自身状态。搜索可以跳回聊天会话中而不丢失已加载的历史。

`wx` 守护进程在收到新的语音留言时会自动下载，独立于浏览器。可见的语音留言会将这些字节加载进浏览器播放控件中；更早的留言仍保留惰性下载回退。文件和视频使用相同的紧凑下载操作与传输任务。不受支持、挂起和过期的资产保留其实际状态；原始 XML 绝不会作为附件展现。会话和查看器共享传输状态，因此打开查看器不会触发另一次传输。

通用的头像组件跟踪其在列表、群头像拼图、详情和消息中的可见性。缺失的可见头像会立即拉取；已缓存的可见头像在距离上次成功从 Hub 读取满一小时后刷新。重新加载页面将恢复此前的时间戳，而不是重新开始计算一小时。屏幕外的头像不会刷新。多个视图共享每次请求，如果最后一个可见视图消失，已排队的刷新将被跳过。群聊列表行最多显示 4 名成员的头像，并且只请求这些头像。在聊天打开处理已读状态期间，头像刷新会暂停。头像读取与媒体发现从视口处开始，因此屏幕外的历史记录不会对 Hub 造成请求洪泛。

符合条件的传入表情在消息展示时会自动加载。浏览器渲染经过校验的原始图片，包括 GIF 动画。模拟器通过其本地适配器提供限定在账号范围内的双帧 GIF；它绝不会去拉取虚拟的表情 URL。原生表情下载保留了严格的来源、完整性、大小和帧数校验。发送表情、表情包、收藏夹及外发表情选择器暂未实现。

**“添加附件” (Attach file)** 会打开一个包含接收者和附件类型的确认框。浏览器预览环境支持最大 25 MiB 的文件；原生后端对各类文件有独立的上限。可选择文件、图片、视频或语音；语音的预处理与切分在现有的 Rust 任务流水线中完成。客户端在跨刷新时仅保留来源 ID、文件名和任务回执，绝不保留文件字节。被拒绝、部分成功及不确定的结果保持相互区分。**“检查状态”** 仅读取相同的回执；不确定的发送绝不会自动重试。

模拟器现已提供经过校验的 PNG、文本、MP4 和 SILK 固件，并通过其解码后的本地传输通道接收外发多媒体。生产环境的预处理、回读校验、幂等性、取消、登出围栏及官方格式历史写入仍由真实的 Hub 运行。这些检查不代表真实的微信服务器验收或接收方播放能力。

## 打开会话

近期的聊天历史记录跨会话切换与页面刷新保持缓存：工作集中最多保留 20 个聊天和 5,000 条消息，淘汰最近最少使用的会话。在客户端校验最新会话数据期间，已缓存的侧边栏保持可见。返回时，在展示缓存的消息正文前会先追赶错过的事件，并对照当前来源代际校验第一页历史。来源变更、过期事件游标以及重置的事件日志都会丢弃旧的历史，同时保留已验证的媒体和头像。保存的字节在展示前仍必须与最新的授权媒体元数据相匹配。撤回会移除缓存的媒体并涂黑缓存的引用摘录。过多积压的追赶会回退到重新拉取新页面。

在连续的事件流中，已读的已缓存聊天无需额外的历史请求即可重新打开。返回前台标签页还会刷新所选聊天和会话角标。当消息仍处于保留的页面中时会恢复滚动位置；恢复位置不会拉取额外的历史。草稿文本与引用在页面刷新后依然保留；引用在使用前会重新校验。

客户端在成功加载选中的聊天后，会将未读历史标记为已读。在加载前会先拉取最新的已读版本；发生冲突时会在重试前重新加载一次版本和历史。绝不会仅通过替换更新的版本来针对未见过的消息进行重试。连续冲突将报错。加载失败以及来自先前选中的聊天的响应不会清除角标。文本回复、引用回复和附件发送同样会确认已加载聊天的当前已读版本。该确认独立于发送操作运行；已读确认失败绝不会重新提交回复。冲突会刷新角标并保持新到达的消息处于未读状态。跨设备已读同步由 Hub 处理。

消息事件仅刷新发生更改的消息和会话。已读状态事件刷新该会话的角标（包括远程已读），群更新刷新受影响的群聊。头像元数据事件不会重新加载联系人清单。联系人/能力加载和群详情不会阻塞首屏历史记录。第一页包含 40 条消息；更早的页面每页包含 100 条。当前 Hub 的分页机制在切分页面前会构建完整的会话快照，因此冷启动打开仍包含此项服务端开销。

会话使用 Headless 的 shadcn Message Scroller。打开聊天从底部开始，并随着图片和其他内容的加载紧跟视口。向上滚动会解除跟随；点击 **“最新消息” (Latest messages)** 可恢复跟随。加载更早的消息时保持可见消息位置不变。搜索使用独立视图。

群头像首先使用缓存的 Hub 字节。打开群聊时会惰性请求可见消息发送者和标题头像拼图缺失的头像；打开其成员列表时对可见行执行相同操作。这些请求使用现有的单人头像刷新操作，带有去重且同时最多并发 4 个刷新。客户端在打开群聊时不会下载整个成员名单。缺失或不可用的照片保留首字母。

## 新建聊天与群组

会话列表使用 Threads API 返回的 `lastMessage` 和 `avatarMembers`。聊天按最新消息优先排序。传入和已接受的外发更新会通过事件流重新排序列；时间相同或缺失则保留原有的相对顺序。单聊展示一个头像；群聊展示最多 4 名已保存成员的拼图头像，名单数据缺失时展示群图标。第二行预览最新保存的消息，外发文本前缀为“你”，并标明传入的群消息发送者。多媒体获得简短标签。本地历史为空与不可用处于不同状态。这些摘要是在分页后从当前 Profile 快照中读取的；不会新增存储表、启动网络刷新或拉取附件。

**“新建会话” (New conversation)** 打开联系人选择器用于私聊。**“新建群组” (New group)** 允许你可选输入群名并选择 2–40 位其他联系人。自身联系人和“文件传输助手”被排除在外。UI 使用 Hub 的 `groupMutations` 能力以及现有的管理员级群 API。

**“会话详情” (Conversation details)** 展示已保存的群信息和所有已保存的成员页面。可用于重命名群组、编辑自身群昵称、添加/移除成员、开启/关闭免打扰、清除公告或退群。退群操作会弹出确认框，保留已缓存的历史记录，并在确认成员身份终止后禁用新消息发送。微信服务端会独立检查权限并分别返回成员操作结果。不支持通用公告编辑、群主转让以及合并后的普通群 API 范围之外的邀请功能。

每次变更都保留一个稳定的密钥和操作回执，限定在服务器、账号和群组范围。页面刷新和 **“检查状态”** 仅读取该回执/密钥。未知或 `needs_review` 的结果予以保留，绝不自动重新提交。部分成员结果与未确认的成员保持可见。只有在后端执行第一步提交之前才支持取消。

**“刷新群组” (Refresh group)** 请求当前的群详情和成员，随后重新加载已保存的视图。`group.updated` 事件也会触发刷新。跨设备更新是不完全的，因此不保证能够自动接收手机端的每一处修改。未知的成员身份保持未知，编辑操作需要确认当前的成员身份。

开发预览环境通过与原生后端相同的 Core 准入、单次尝试操作日志、编解码器校验以及 Profile 投影在本地模拟器中实现这些请求，仅替换了本地固件响应。本 UI 未使用任何官方端点进行验证。虚拟系统通知使新的模拟群聊在会话中可见；系统通知不会触发 OpenClaw Agent 轮次。

## 账号与会话详情

设置中可以重命名选中的账号并执行登出，在响应丢失或刷新后具备确认提示与同操作状态恢复能力。登出操作会将历史记录保留在 Hub 上。登出或 `auth_required` 事件会使浏览器返回账号选择页面，并停止该账号的数据流、上传和媒体请求。返回浏览器时还会检查账号认证状态。已拉取的浏览器缓存将被清空；草稿和挂起的操作回执在登录后依然可用，无需自动重发。登录在选中账号时发起，优先尝试已保存的凭据，当 Hub 无法使用已保存登录时回退到二维码。微信可能会要求在手机上确认。现有的挂起登录会恢复同一操作。

| 登录场景 | 浏览器行为 |
| --- | --- |
| 新账号或无可用设备信任 | 显示 Hub 提供的二维码 |
| 活跃会话中 | 恢复并打开聊天 |
| 已登出但拥有受信任的已保存设备 | 无需二维码直接登录 |
| 微信要求手机端确认 | 等待确认，随后打开聊天 |

手机确认可出现在扫码之后或基于保存设备的登录之后。Hub 会向微信校验已保存的凭据；保留凭据并不保证它们依然有效。

会话详情展示带有悬停标签的内部会话 ID、群设置和成员。已读确认和可见头像刷新自动运行。已缓存的头像替代首字母；缺失头像保留首字母。群详情加载所有成员列表页。

| 区域 | 当前浏览器端行为 |
| --- | --- |
| Hub 与账号 | 模拟器引导、Bearer 连接、账号创建/切换、重命名与登出 |
| 登录 | 二维码 PNG、倒计时、自动刷新、手机确认及自动进入聊天 |
| 会话 | 联系人、会话过滤、分页历史/搜索、完整群成员名单、已读状态、头像及群控件 |
| 消息收发 | 文本与附件编辑器、进度、回执状态、不确定性处理、自身发送与 SSE 重放 |
| 多媒体 | 图片/视频/语音预览、下载、传入动态表情及外发文件/图片/视频/语音任务 |
| 设置 | 外观与账号控制；Agent 配置与桌面设置待后续跟进 |
| 分发 | 浏览器开发预览；生产环境托管与 Tauri 打包待后续跟进 |

## 验证

```sh
pnpm --filter @agent-wechat/client-ui test
pnpm --filter @agent-wechat/shared test
pnpm build
pnpm typecheck
pnpm native:simulator:smoke
pnpm client:smoke
```

模型测试涵盖迟到的账号/会话响应、分页历史与清单、规范内容事件、发送/提交竞态、稳定的不确定发送、首帧连接状态及游标恢复。浏览器端验证使用真实的 Rust Hub 和模拟器。虚拟测试结果不代表官方客户端兼容性或真实的微信服务验收。

扩展的客户端完整流程在非 root、只读且禁用外部网络的容器中运行。包含传入媒体完整性/范围/账号隔离、GIF 动图帧、外发预处理与回读、拒绝与响应丢失、回执恢复、账号别名、版本化已读状态、缓存头像及登出。修改解码后的传输协议需要通过固定的 Rust Format/Clippy、原生测试及生成的契约检查。自动化完整流程使用 Rust 模拟器，不接触任何真实端点。

Linux x64 验证（包含会话摘要）：在非 root、只读且禁用外网的容器中通过了 20 个可执行文件共 527 项 Rust 测试。Rust Doc 测试、固定的 Format/Clippy 及生成的契约均通过。客户端通过了 43 项模型测试，SDK 41 项，OpenClaw 239 项；工作区构建与类型检查通过。两项完整的模拟器流程均顺利通过。

群聊测试流程校验了创建/重命名、自身群昵称、免打扰开启/关闭、添加/移除、公告清除、刷新以及保留历史的三步退群。还校验了部分成员接受、服务拒绝、丢失准入响应、丢失上游确认、同密钥状态恢复以及账号隔离。显式连接启动器还额外通过了本地 HTTP 固件关于引导授权、源检查、纯账号代理、拦截所有者路由以及保持外部守护进程运行的检查。只读 Linux x64 原生浏览器检查确认了账号准入、已存会话、消息预览、缓存头像和群详情。真实账号上的浏览器变更流和桌面打包仍未进行实际验证。
