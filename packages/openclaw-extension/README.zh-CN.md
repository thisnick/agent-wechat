# OpenClaw 微信频道 (OpenClaw WeChat channel)

[English](README.md) | [简体中文](README.zh-CN.md)

本插件使用独立的原生守护进程。外部模式（External mode）通过端点和令牌连接到独立运行的守护进程（包括原生服务器容器）；Gateway 既不需要 `wx` 也不需要 Docker 工具。托管模式（Managed mode）会启动其拥有的本地守护进程，需要单独安装 `wx`。插件的安装与启动绝不下载或修复二进制文件。旧版容器 API 配置需要进行显式迁移。

发布后，使用 `openclaw plugins install @agent-wechat/agent-wechat@beta` 安装原生 Beta 版本，或锁定其确切版本。在 Beta 测试系列期间，稳定的 `latest` 渠道继续选择旧版容器插件。

## 原生外部模式 (Native external mode)

在 `plugins.entries.agent-wechat.config` 下配置插件默认项（或在 channel 中配置相同的 `native` 项）：

```json
{
  "native": {
    "mode": "external",
    "accountId": "example",
    "endpoint": "http://127.0.0.1:6174",
    "token": { "source": "env", "provider": "default", "id": "AGENT_WECHAT_TOKEN" },
    "consumerStateDir": "/private/openclaw-native-consumer",
    "readPolicy": "on_inbound"
  }
}
```

外部服务保持独立拥有。插件停止时仅关闭其数据流，绝不停止或登出守护进程，也不会取消其发送任务。远程端点需要经过验证的 HTTPS 或终止于环回地址的加密隧道。在 Gateway 进程环境中设置 `AGENT_WECHAT_TOKEN`，或使用已配置的 OpenClaw Secret 提供者。插件通过锁定的 OpenClaw SDK 解析 `native.token`；已移除 `native.tokenFile`。令牌包含 32–1024 个不含空格的可打印 ASCII 字节。显式未解析的引用会导致启动失败，而不会回退到其他令牌。API 令牌对所选账号需要拥有 read/media/send/login 权限，并且仅在启用自动整会话标记已读时才需要 read-state 权限；切勿仅为运行插件而授予 admin 权限。常规发送者/私聊/群聊/提及（@）策略仍保留在 `channels.agent-wechat` 中；默认保持关闭。

## 登录工具 (Login tool)

通过 OpenClaw 的工具策略，配置的 Agent 可以使用 `wechat_login`，包括在微信离线时从其他频道调用。使用 `{"action":"status"}` 检查账号状态，`{"action":"start"}` 启动或恢复登录并显示返回的二维码图片，随后使用 `{"action":"wait","timeoutMs":30000}` 检查扫码/确认完成情况。重复执行 start 会复用挂起的操作。对于新操作，`force: true` 会强制使用二维码而非已保存的设备信任。等待具有时限，并报告操作 ID 和状态。取消工具调用会保留已提交的登录操作供后续调用使用。

该工具还接受 `disconnect`（保留已保存信任）、`logout`（持久化原生登出）以及带 `confirm: true` 的 `forget`（删除本地认证，保留历史记录）。它始终绑定到配置的守护进程与账号。通过应用 OpenClaw 工具允许/拒绝策略来控制哪些 Agent 可以管理登录。该工具可被直接调用，因此守护进程生成的 PNG 图片能够以图片内容形式直接递送给模型。

## 原生托管模式 (Native managed mode)

```json
{
  "native": {
    "mode": "managed",
    "accountId": "example",
    "executable": "/opt/agent-wechat/bin/wx",
    "listen": "127.0.0.1:6174",
    "dataDir": "/private/native-store",
    "token": { "source": "env", "provider": "default", "id": "AGENT_WECHAT_TOKEN" },
    "consumerStateDir": "/private/openclaw-native-consumer",
    "readPolicy": "never"
  }
}
```

原生可执行文件与账号注册需单独配置。省略 `executable` 会从绝对受信任的 PATH 环境变量条目中解析一次 `wx`。插件通过直接选择已安装且校验和匹配的 ELF 载荷来支持经过测试的 npm 启动器布局。它绝不调用安装器或 Shell。未知的包装脚本/旧版容器 CLI 会被拒绝。托管启动会拒绝被占用的端口，并要求经过认证的就绪状态与所拥有的子进程 PID、存储路径、服务器身份及进程代际相匹配；它绝不接管或终止其他进程。停止操作会向自身子进程发送正常终止信号并受限升级。意外的子进程/数据流故障会被上报；此版本未实现进程崩溃自动重启。

托管启动通过私有的 stdin 管道传递解析后的令牌；它不创建令牌文件，也不将令牌放入参数或守护进程环境中。托管的 `serverConfig` 必须省略 `tokenFile`。重新加载/重启 Gateway 以更改凭据或机密提供者配置。

请将 `dataDir` 和 `consumerStateDir` 保持在独立的显式持久挂载卷上。守护进程拥有官方格式的 Profile/Sidecar 数据；消费者目录保存绑定到服务器和账号身份的私有接入/去重/模型交接/已读回执。可执行文件升级不会删除任何一个目录。在此版本中，一个配置的 OpenClaw 账号映射到一个选定的原生守护进程账号，而守护进程本身支持独立的账号槽位。

## 原生消息生命周期与校验限制

适配器使用 Bearer 请求头和十进制字符串日志游标来消费账号限定的 SSE 数据流。它在确认游标之前持久化保管状态；确认独立于未读状态。只有显式实时的、传入的、已提交的资源才能输入模型。受支持的图片、简短语音、视频、文件和符合条件的表情通过受限的媒体检索和哈希校验进入 OpenClaw 管理的存储中。挂起中的媒体保留保管权，而不进行模型调度或生成已读回执。过期/不支持的附件保留明确的状态；原始 XML 绝不成为附件。追赶/导入/未处理的暂存同步批次、未知来源以及传出消息不会自动作为模型输入。群聊准入采用结构化的确切自身提及事实；未知的元数据或显示的 `@昵称` 绝不满足提及门禁。联系人和群组使用各自独立的目录。

每个就绪的附件都会在消息正文和 `Attachments` 元数据中提供其在 OpenClaw 管理下的原始路径（包括图片）。文件引用使用尖括号包裹路径，例如 `[Image file: <path>]` 或 `[Local file: <path>]`，因此 OpenClaw 在扫描 Prompt 文本时不会自动加载原文件或带有图片扩展名的文件。单独准备的图片预览可能占用 `MediaPath`，而原文件仍可通过其自身路径访问。文件、语音和视频保留明确的本地引用；可用路径并不声明模型分析了该文件。

在需要提及的群聊中，通过发送者准入但未提及的消息将作为上下文保留，而不进行检索、转录、模型轮次或已读通知。下一条准入的非命令消息在再次检查当前发送者策略后会包含该上下文。`messages.groupChat.historyLimit` 控制每个群的窗口大小（默认 50，最大 200；0 为禁用）。消费者存储总体最多保留 1,000 条缓冲的群消息。上下文在 Gateway 重启后依然保留。在调度时，选定的上下文与持久化轮次记录原子消费，因此不确定的轮次不会自动再次提供。原始提及事实保持不变；历史记录与触发消息分开记录。

群消息追赶最多使用 3 个 Worker 检索媒体，保留每个经过验证的原始路径，并仅选择最新就绪图片的预处理版本供视觉模型使用。挂起或不可用的历史附件保留明确状态，不会阻塞当前的提及处理。触发消息的附件如果仍在挂起中，会继续挂起自身的调度。语音转录仅在准入和激活后运行。命令不会消耗已缓冲的上下文。

默认情况下，`readPolicy: "on_inbound"` 会在传入消息被持久化存储、通过发送者/群组/提及检查并完成正常的 OpenClaw 传入处理后，将整条会话标记为已读。在未调用模型的情况下，内置命令也符合此条件。此策略不检查模型输入，也不需要 `hooks.allowConversationAccess`。被忽略的消息、挂起的媒体以及处理失败的消息不会触发已读标记。已读意味着已被集成模块处理；并不代表模型分析了附件。

整条会话标记已读还会清除该会话中较早的未读消息，包括模型未接收的消息。守护进程冻结最新的本地消息边界、检查预期版本、更新本地未读状态并提交一次原生已读状态通知。仅服务端接受并不能证明手机端角标已发生变化。丢失的通知响应保持为 `needs_review`，绝不自动重新提交。挂起的已读在 Gateway 重启后依然保留，并独立于模型执行或新的 SSE 流量进行重试。`readPolicy: "never"` 禁用本地和远程标记，包括先前已排队的已读。未完成调度期间发生崩溃会保留 `needs_review`；插件不会自动重复模型轮次或不确定的传出发送。

可选的 `readPolicy: "on_model_dispatch"` 则需要确认的模型交接。OpenClaw **2026.10.7** 缺少 `onPreparedAgentRunStart`，因此其已发布的公开 Hook 提供了一条受限的兼容路径。在调度之前，适配器持久化一份不可变清单，绑定确切的新消息 ID/版本/内容哈希、策略哈希、来源和提供的资产哈希以及上下文角色。文本需要确切的当前输入、宿主创建的消息/账号/会话事实，以及匹配的 `model_call_started`。多媒体还需等待同一次运行的 `agent_end` 快照和来源轮次标识。图片字节/MIME/长度必须与冻结的提供表示一致；文件/视频/语音引用必须出现在确切的当前正文中。仅靠图片数量、模型选择和回复递送无法确认模型交接。未知、遗漏、重写、合并或有歧义的输入保持未确认。宿主/提供者历史格式可能会阻止确认，即使已递送回复；对于常规 Bot 已读行为，建议使用 `on_inbound`。

模型交接兼容路径需要操作员显式授予宿主权限：`plugins.entries.agent-wechat.hooks.allowConversationAccess: true`。它仅观察由此适配器发出的运行 ID，绝不自行开启该权限。未授权或在不受支持的宿主上，显式的 `on_model_dispatch` 策略将保持消息未读，状态报告为 `handoffUnconfirmed`。旧版的 `onAgentRunStart` 也会报告直接工具和早期生命周期阶段，绝不作为证明凭据。访问和提及门禁仍先于模型调度执行；被拒绝的消息本身不会触发已读。

超过宿主受限表示的图片，或需要格式转换的图片，会使用公开 SDK 图片处理器生成单独存储的 JPEG 静图预览。原图保持不变；记录两者的哈希，并在模型输入中标记预览图。预处理图片限制在 5 MiB 以内且每边最多 1200 像素（或更小的配置限制）。文件和视频可作为可用的本地引用提供；这并不表明它们的内容已被分析。语音保留其经过验证的文件，并包含配置的转录输出或明确的不可用状态。在 `on_model_dispatch` 下占位符无法确认模型交接；默认的 `on_inbound` 可以在成功处理明确的过期/不支持状态后标记会话已读。

## 消息撤回 (Message recalls)

`wechat_recall` 用于撤回配置的微信账号在当前会话中发送的消息。传入 `{"messageId":"<不透明的存储ID>","serverId":"<精确的十进制服务器ID>"}`，这两个值需取自相同的已验证发送回执或 `wechat_history` 条目。服务器 ID 保持为字符串格式，包括大于 JavaScript 安全整数范围的值。本地不透明 ID 可以被复用，因此带有不同服务器 ID 的旧引用会被拒绝。发送/任务/操作 ID 无法替代存储的消息 ID。

该工具使用 OpenClaw 受信任的账号、会话和请求者上下文。它不接受账号或会话选择器，重新检查常规请求者策略，并要求是自身发出的消息；所有者身份和归档访问权限不会扩大撤回权限。守护进程做出最终的资格决定。账号令牌需要 `read` 和 `send` 权限。常规 OpenClaw 工具策略可以禁用 `wechat_recall`。

确切的已撤回占位符可能会在官方 Profile 中丢失其原发送者归属性。针对该占位符重复调用该工具将通过守护进程检查其保留的已撤回状态，且无法开启另一次原生撤回；结果会标记为 `action: "inspect_recalled"`。

每个目标都会获得一个稳定的幂等键和持久化操作。只有确切成功的凭据才会报告 `recalled` 或 `already_recalled`。拒绝、`pending` 和 `needs_review` 保持明确。丢失响应或取消操作不会导致另一次自动 POST，也不会取消守护进程的操作。请保留上报的操作 ID 和密钥以供检查；切勿提交替代操作来解决不确定性。

原生文本、图片、文件、视频和语音投递结果在通过账号/会话/服务器身份验证后返回实际存储的消息 ID。`meta.messageIds` 为切分的语音留言保留每个经过验证的回执，并附带持久化的发送/任务 ID。已接受的媒体任务可能会稍晚发布其存储的回执；适配器对同一任务最多检查 10 秒，并要求每个已接受语音块的回执。如果存储的回执仍不可用，结果将使 `messageId` 为空，并上报 `receiptState: "needs_review"` 及 `retryable: false`；已被接受绝不是重发的理由。失败、部分成功及不确定的任务不进入回执等待。

传入的 `message.recalled` 事件与耗时的媒体和模型处理独立消费，包括对自身或未提及消息的撤回。消费者持久化保存事件游标及逻辑删除标记（Tombstone），从其保管记录中移除已撤回的正文/引用内容和附件引用，并使挂起的模型证明失效。逻辑删除标记在重启后依然存在，并能抑制迟到的原消息。附件检索、转录、模型调度以及随后的自动回复递送都会重新检查所选消息，因此迟到的处理无法重新插入已撤回的输入。撤回原消息后，引用的无关评论仍保持可用。

收到的引用消息使用微信服务端协议投递的解析后内嵌内容，包含在常规消息响应的 `quote` 字段中。文本和链接详情立即可渲染；图片元数据可在回复消息自身的 ID 下检索经过验证的字节。其他被引用的多媒体保持当前评论并显示不可用的附件状态。本地撤回抑制和引用作者准入仍然适用，包括在历史工具中。已存储的原消息绝不会替代内嵌摘录；引用展示无需独立的引用端点。

如果源本地消息 ID 随后指定了不同的确切会话/服务器目标，消费者会以独立的宿主轮次和回复密钥准入该新消息。为旧目标捕获的完成回调、媒体结果和已读回执无法覆盖新的保管记录。

已存储历史工具会返回已撤回占位符；媒体工具返回终止状态 `status: "recalled"`、`reason: "message_recalled"`、`retryable: false`，且不附带附件路径或图片块。撤回操作不会抹去已经提交的模型输入、现有的 OpenClaw 交互记录、已完成的动作或 OpenClaw 存储策略保留的附件字节。受影响的进行中轮次会被挂起以待审核，并抑制其随后的自动回复；插件不承诺追溯性修正交互记录。

旧的媒体句柄如果其存储来源发生更改，或其来源身份无法验证，将返回终止状态 `unavailable`，原因标注为 `media_source_changed` 或 `media_identity_unavailable`。它们不暴露任何缓存路径，也不会自动重试。全新发现已存储消息可以直接选择预期的当前消息及其绑定的缓存资产，而无需重新发送微信消息。

`node scripts/native-recall-model-smoke.mjs` 会构建实际插件，并在模拟原生 HTTP/SSE 和本地 Provider 的情况下运行锁定的 Gateway。它检查已注册工具发现和精确目标执行、稳定的重复密钥、其他会话的拒绝、在 Provider/媒体请求受阻时的撤回接入、迟到输出抑制、乱序撤回保管，以及复用源 ID 的新精确占位者的单次调度。它不进行真实的账号或原生协议交互。

## 已存储历史工具 (Stored-history tools)

Agent 可以使用所选原生账号的本地 Profile 查看近期传入缓冲区之外的内容：

| 工具 | 输入参数（`?` 表示可选） | 输出 |
| --- | --- | --- |
| `wechat_history` | `{ limit?, cursor? }` | 已存储消息（最新优先），包含 `nextCursor`、`sourceGeneration` 和 `coverage` |
| `wechat_search` | `{ query, limit?, cursor? }` | 相同的页面结构，按不区分大小写的子字符串过滤 |
| `wechat_message` | `{ messageId }` | 单条已存储消息 |
| `wechat_media` | `{ messageId, download?, quality? }` | 媒体状态、可选的已验证文件路径和图片内容 |

一条已存储的消息包含 `id`、`threadId`、可空的 `serverId`、`senderId`、`direction` 和 `createdAt`、数字 `type`、受限的 `body` 以及 `bodyTruncated`。其可选的 `attachment` 描述符包含 `kind`、`messageId` 和 `retrievalTool: "wechat_media"`。消息 ID 和服务器 ID 保持为字符串；使用不透明的 `id` 进行精确查找和媒体检索。

媒体结果包含 `messageId`、`threadId`、`status` 和 `retryable`，附带可选的 `attachment`、实际 `variant`、`jobId`、`reason` 和用于展示的 `body`。就绪的附件具有 `kind`、`filename`、经过验证的本地 `path` 和 `mime`；图片质量可能为 `full`、`standard` 或 `thumbnail`。不可用的结果绝不声称存在本地路径。OpenClaw 将结构化输出封装在 `details` 和文本 `content` 中；就绪的图片会额外提供图片内容块。

例如，Agent 可以在当前会话中调用 `wechat_search`，传入 `{"query":"项目笔记"}`。这四个默认工具被限制在从受信任的 OpenClaw 上下文派生的当前微信账号和会话中。拥有归档访问权限的所有者和 Agent 在调用默认工具时受到相同的限制。默认工具不接受会话/账号选择器，插件会拒绝来自其他会话或账号的消息或资产。请求者和历史发送者策略会被重新检查。缺失或冲突的受信任会话上下文会隐藏默认工具；Webchat 和其他频道无法使用它们。

历史/搜索返回不透明的字符串消息 ID、受限的文本预览、覆盖率元数据和 `nextCursor`。使用相同的工具、查询和会话传回游标以继续翻页；每页数量限制为 1–50（默认 20）。搜索查询限制为 256 个 UTF-8 字节。较长的消息正文会标记为截断。经过发送者过滤的页面可能为空但仍有后续翻页。搜索覆盖本地存储的历史记录，不拉取缺失的远程历史，也不维护官方 FTS 索引。多媒体消息会收到类型/状态说明；这些工具不返回原始传输 XML 也不下载附件。历史、搜索和单条消息查找是只读的。其附件描述包含 `wechat_media` 和确切的消息 ID，而不会自动检索多媒体。这些工具均不会将会话标记为已读、发送消息或修改传入消费者游标。查找需要所选账号的 API `read` 权限范围，并仍遵循常规 OpenClaw 工具策略。在 OpenClaw 的精简工具目录中，Agent 通过 `tool_search` 发现历史/搜索/消息查找，并通过 `tool_call` 调用返回的工具。媒体工具保持直接可作为 `wechat_media` 调用：锁定宿主的通用包装器将嵌套图片块序列化为 JSON 文本，而直接调用保留图片内容供视觉模型使用。

`wechat_media` 接受 `{"messageId":"<返回的不透明ID>"}`。它在访问资产前验证消息/会话/发送者准入，优先使用缓存字节，检查身份、哈希和大小，并将经校验的字节保存到 OpenClaw 管理的媒体存储中。文件、视频和语音返回本地路径；图片还会返回受限的预处理预览作为视觉模型使用的图片内容。此检索本身不转录语音或分析文件/视频。缓存字节在 CDN 过期后依然可用。

缺失的媒体默认会请求持久化的守护进程传输任务，带有 2 秒的受限等待。挂起的结果包含已知时的 `jobId` 且不声称拥有本地路径；稍后可以使用相同的消息 ID 再次调用同一工具进行检查。守护进程拥有并去重该传输任务，因此取消工具调用不会取消已提交的任务。使用 `download: false` 仅获取已缓存的媒体。`quality` 默认为 `best`（最佳缓存图片、标准视频或解码语音）；显式的 `original`、`standard`、`thumbnail`、`normal` 和 `encoded` 变体要求严格且可能不可用。结果会报告实际变体以及明确的 pending、expired、unsupported、unavailable 或 too-large 状态。对于 `retryable: false` 或确认过期的状态切勿自动重试。媒体工具需要账号限定的 API `read` 和 `media` 权限，包括下载请求。绝不返回原始 XML、签名的传输 URL 和密钥。

`node scripts/native-history-model-smoke.mjs` 使用本地账号/媒体/模型固件演练锁定的 Gateway：持久化群上下文、原始文件路径、带有验证哈希的单一预览、作为文件发送但保留引用的 PNG、直接图片投递、实际工具发现、两次分页搜索调用、访问媒体前拒绝其他会话的附件、一次请求的图片下载且其确切图片字节进入视觉输入，以及进入 Provider 的缓存文件路径。CI 在两种 Linux 架构上运行此检查。

当资产元数据标识现有的下载任务时，检索会轮询该范围限定的任务，而不是提交另一次传输。终止任务的原因和可重试性均予以保留，包括在仅缓存模式下；此工具不会自动重试失败的任务。仅凭服务端拒绝并不能归类为过期。

### 特权归档工具 (Privileged archive tools)

五个可选工具可以跨配置的原生微信账号中的所有会话进行读取：

| 工具 | 输入参数（`?` 表示可选） | 输出 |
| --- | --- | --- |
| `wechat_archive_threads` | `{ query?, limit?, cursor? }` | 会话页面：`id`、`peerId`、`kind`、`displayName`、`unreadCount`，以及分页和覆盖率 |
| `wechat_archive_search` | `{ query, threadId?, limit?, cursor? }` | 跨所有会话的消息页面；可选的 `threadId` 用于缩小范围 |
| `wechat_archive_history` | `{ threadId, limit?, cursor? }` | 所选会话的消息页面（最新优先） |
| `wechat_archive_message` | `{ messageId }` | 来自任意会话的单条消息 |
| `wechat_archive_media` | `{ messageId, download?, quality? }` | 来自任意会话的经校验附件状态/路径和图片内容 |

消息/页面/媒体的输出结构、边界和下载行为与上述默认工具一致。归档附件描述符将其检索工具指定为 `wechat_archive_media`。会话查询匹配本地存储的 ID 和显示名称。搜索使用守护进程的账号级 `GET /v1/accounts/{accountId}/messages?query=...` 端点；其不透明游标绑定账号、查询和会话选择，并跨本地编辑、删除和新消息保留成员关系/顺序。搜索读取具有受限快照容量的本地 Profile；它不回填远程历史。缺少该端点的旧版守护进程必须升级才能支持全账号搜索。

在 OpenClaw 的 `~/.openclaw/openclaw.json` 中配置访问权限，合并到现有的命名 Agent 条目中：

```json
{
  "agents": {
    "ownership": "explicit",
    "entries": {
      "main": {
        "tools": { "alsoAllow": ["wechat_archive_*"] }
      },
      "group-bot": {
        "tools": { "deny": ["wechat_archive_*"] }
      }
    }
  }
}
```

OpenClaw 对工具执行和目录发现实施这些策略。`main` 名称没有隐式特权。可以使用单独的工具名称来授予子集。如果 Agent 已配置 `tools.allow`，请将归档工具名称添加到该列表中，而不是将 `allow` 和 `alsoAllow` 混合使用。全局拒绝依然优先于单个 Agent 的允许。未配置选取策略时可选工具不会出现，但 `profile: "full"`、`*`、`group:plugins` 或对整个 `agent-wechat` 插件的允许也会选中它们；对于应仅保留当前会话访问权限的 Agent，需显式配置单 Agent 拒绝。

不存在插件权限列表、所有者例外或归档发送者/会话过滤器。宿主授权的归档调用可以从任意频道读取配置的账号，包括群聊调用。当某些运行应具有更窄的访问权限时，请使用 OpenClaw 的发送者策略或将群聊流量路由到不带归档工具的 Agent。归档工具始终绑定到配置的账号，并校验消息/资产的身份、哈希和大小。它们绝不接受任意文件路径或其他账号选择器。常规账号/令牌范围检查和调用取消围栏依然生效。

历史/搜索/消息/会话读取操作绝不发送消息、标记会话已读或修改传入游标。归档媒体可以提交与 `wechat_media` 相同的受限、去重下载任务；它保持直接可调用，以便实际的图片块能够进入视觉模型。

运行 `node scripts/native-archive-tools-smoke.mjs` 在具有三个独立路由 Agent 的情况下检查锁定的 Gateway：无可选工具授权、带有显式拒绝的完整 Profile，以及归档授权。它检查发现与猜测名称调用的拒绝、跨会话搜索分页、其他发送者历史/媒体、未改变的默认工具范围、Provider 输入中经过验证的图片字节以及缓存的文件路径。本测试中的所有消息、账号数据和模型响应均为虚拟数据。CI 在 Linux x64 和 ARM64 上运行该项测试。

在安装工作区依赖后，运行 `node scripts/native-model-smoke.mjs` 和 `node scripts/native-media-model-smoke.mjs`。它们使用锁定的实际 Gateway、本地模型以及虚拟守护进程/文件。检查涵盖无会话权限的默认传入已读、无模型调用的命令、当前 Provider 输入、图片哈希与预处理预览、引用/转录递送、整会话已读请求、响应丢失/重新打开恢复、防重复、纯文本模型上的遗漏图片、显式模型交接权限、从不标记已读策略以及群路由行为。转录使用真实 SDK 并配置显式的本地确定性 CLI；它不测试语音识别准确率。并发文本输入被串行化为不同的模型轮次；合并输入拒绝针对显式模型策略具有单元测试覆盖。这些检查确认本地运行时行为，不代表外部 Provider 的接受、语义分析或消费。

原生文本/媒体发送保留守护进程意图/任务标识以及调用方幂等性。文本等待被接受的提交；媒体任务保留部分成功和不确定的结果，而不是重新发送。普通音频保持为文件；只有显式的 `audioAsVoice` 会请求独立编码的语音。发送者/群组/提及门禁在检索/转录之前运行。验证的语音在准入后可以使用配置的 OpenClaw 转录运行时。原生二维码登录使用持久化的守护进程操作和经过认证的 PNG 检索。登出在最多执行一次经认证的原生登出前提交本地抑制，单独上报远程结果；已保存设备吊销仍未经验证。显式确认的遗忘会在保留历史的同时删除本地认证；断开连接会保留可复用的信任。

## 外发附件大小限制

`channels.agent-wechat.mediaMaxMb` 限制传入保留的附件和外发媒体源的大小（以 MiB 为单位）。外发媒体源还必须符合所选类型的原生限制：普通文件上限为 512 MiB（536,870,912 字节）；视频源允许 50 MiB；图片和语音保持 26,214,383 字节。原生文件传输助手在 32 MiB 和 50 MiB 下通过了 PDF 验收、接收方打开及冷启动字节验证。完整客户端 512 MiB 发送验证仍在进行中。50 MiB 文件也通过了真实的 OpenClaw 存储；参见[原生能力清单](../native-client-rust/FEATURES.md)。调高 `mediaMaxMb` 无法突破特定类型的物理限制。类型选择在暂存前发生，使用本地扩展名或 HTTP 内容类型。普通音频为文件，除非 `audioAsVoice` 选择了语音。

对于超过 26,214,383 字节的普通文件，适配器对提交的同一任务最多轮询 1 小时，允许在最终消息提交前完成上传与精确回读。超时或状态轮询失败会保留任务 ID 和幂等键，绝不自动发送另一份副本。不支持的缓存命中响应或不确定的预留/提交需要手动检查。CLI、HTTP API 和 SDK 示例参见[发送附件](https://thisnick.github.io/agent-wechat/use/media/)。

视频发送默认生成用于播放的预处理 H.264/AAC 副本及缩略图。对于单个视频附件，常规消息工具接受 `channelData: { "agent-wechat": { "videoQuality": "original" } }` 以同时包含未改变的源文件；`"normal"` 仅选择播放副本。设置 `mediaMaxMb` 允许源文件大小。`forceDocument`（或宿主别名 `asDocument`）将多媒体作为普通文件发送，不能与视频质量组合使用。视频任务对同一任务最多轮询 1 小时。有关独立的服务端、接收方和本地回写验证，请参见原生能力清单。

## 可选 Gateway 外观模式 (Optional Gateway facade)

设置 `native.gatewayFacade: {"enabled": true}` 可在 Gateway 上注册 `/plugins/agent-wechat/native`。默认处于禁用状态。自定义前缀必须保持在 `/plugins/...` 命名空间下；修改守护进程配置需要重新加载 Gateway。

真实的 Gateway 会在代理运行前对请求进行鉴权。其 Bearer 绝不转发给守护进程；插件使用其私有的守护进程令牌引用。路由限制在配置的账号内，不存在全守护进程级的令牌/账号管理。二进制正文、字节范围、状态码和 SSE 在显式大小限制内予以保留。客户端断开连接/插件关闭会关闭上游流式传输任务，而不会取消持久化的发送任务。

`scripts/native-gateway-smoke.mjs` 在具有合成环回数据的隔离 OpenClaw **2026.10.7** Gateway 上测试构建的插件：认证拒绝、独立凭据、账号边界、Range 206、SSE 及取消。该传输测试与上述本地模型边界测试相互独立；两者均不使用外部模型提供者或真实微信账号。

详见[原生部署示例](../../deploy/native/README.md)和[原生 CLI 安装说明](../cli/README.md)。
