# Mini Program compatibility

This catalog is for the experimental native Mini Program runner. Start a cached app with
`wx miniprogram serve APP_ID`. To fill a missing main package, use
`wx miniprogram fetch APP_ID` with a hub admin key and an online account.

Source audit: [WeChat Mini Program Demo at `0fe5c7df`](https://github.com/wechat-miniprogram/miniprogram-demo/tree/0fe5c7df8e90582dd0b89e283df7fe32e04413f9)
and the pinned [Skyline examples at `3183f9b4`](https://github.com/wechat-miniprogram/awesome-skyline/tree/3183f9b467eeb579f1c0737c1b83315746952aae).
The manifest declares **356 page routes**. Each has source in the pinned checkout.
The source audit follows literal script imports, template includes, custom component declarations,
and direct API references. It includes conditional references and cannot resolve every dynamic dispatch.
App-wide startup dependencies are listed separately. A capability reference does not prove a page executed it.

The browser probe used cached public demo release **161** with external requests and login exchanges blocked.
The published release and the source revision are separate evidence. A missing page means it was unavailable
in this run with the staged archives. A mount verifies navigation into the view, while feature interactions
require separate tests.

These checks cover startup. Booking, ordering, payment, and complete signed-in flows remain unverified.

## App-wide requirements

| Requirement | Runner behavior |
| --- | --- |
| Main archive and subpackage loading | Verified main archive. Same-release staged JavaScript subpackages can load lazily. Subpackage pages, automatic subpackage download and preload rules remain unavailable. |
| Compiled templates and styles | Glass-easel and selected Exparser pages. Both paths adapt compiled app/page WXSS and responsive units; styles stay outside the host toolbar. Exparser also supports selected component styles. Native Skyline, XR and Mini Game renderers are unavailable. |
| Page navigation and app lifecycle | Main-archive page stack and browser visibility. App tab bar, custom route builders, app bar, and native split frames are unavailable. |
| WeUI extended library and plugins | Require separately supplied code and host support. Extended library resolution and native plugins are unavailable. |
| Cloud development and ads | Cloud database, cloud functions, cloud files and the advertising SDK are unavailable. |
| Workers and AI handoff | Native workers, chat tools, agent entry points, and `wx.onAgentHandoff` are unavailable. |
| Network and files | Authorized public HTTPS requests and a separate display image bridge. Native file storage, uploads, downloads and app WebSockets are unavailable. |
| Platform permissions | Launch login scope and local privacy confirmation are supported. Host permission prompts and native device integrations are unavailable. |

Startup script references: `App`, `getApp`, `require.async`, `wx.canIUse`, `wx.cloud`, `wx.cloud.callFunction`, `wx.cloud.init`, `wx.env`, `wx.getAppBaseInfo`, `wx.getBackgroundFetchData`, `wx.getStorageSync`, `wx.login`, `wx.navigateTo`, `wx.onAgentHandoff`, `wx.router`, `wx.setBackgroundFetchToken`, `wx.setStorageSync`, `wx.showToast`, `wx.worklet`.

The demo also probes `getSystemSetting`, `getAppAuthorizeSetting`, `getDeviceInfo`,
`getAppBaseInfo`, and `getWindowInfo` through computed API names. The last three have
browser implementations. The other two probes are unavailable.
