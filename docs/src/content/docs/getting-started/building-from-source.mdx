---
title: Building from Source
description: Use CI or a native Linux worker for builds and validation.
---

CI is the normal validation path and builds on separate Linux x64 and ARM64 workers. It tests real executables, packaged installers and containers with synthetic data, without deploying. An existing remote Docker context can offload builds; no local cross-compiler is required.

For a developer build on a suitable Linux worker:

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm typecheck
pnpm native:test
pnpm native:build
pnpm generate-types
```

Rust 1.93.1, a C compiler, Node 24.16+ and pinned pnpm 9.15.4 are the source-tool baseline. `pnpm build` builds the SDK, npm launcher checks, OpenClaw bundle and docs; the Rust workspace has its own build/test commands. The library crates remain workspace/git/path dependencies rather than crates.io packages.

`bash scripts/native-build-release.sh` builds/tests the host architecture in Bookworm and emits versioned executable/checksum/notice artifacts. `node scripts/native-package-smoke.mjs artifacts/native` tests a real tarball and offline installation. Local dirty output is explicitly marked and cannot pass publication. Release and image workflows are separately gated; running build/test commands does not publish or deploy.

Changesets generates package versions and changelogs in the version PR. The approved native release workflow uses the exact CLI/OpenClaw entries from those changelogs as GitHub release notes, preserving their Markdown and links. It does not read pending changeset files after versioning. Missing/version-mismatched or entirely empty notes block release preparation. Retries refresh only the generated Changesets block and retain operator notes outside it. `node scripts/native-release-notes.mjs --output /tmp/agent-wechat-release-notes.md` previews the committed version's notes locally without publishing.


## Beta release process

The native rewrite starts with **`1.0.0-beta.0`**. Both public packages share the version; the private bundled SDK is versioned with its own changeset. `beta` is an explicit npm opt-in, while `latest` stays on the existing stable container implementation. GitHub beta releases are marked prerelease and are not marked Latest. Image tags include the exact prerelease version.

No local build or publication is required:

1. Merge the reviewed implementation PR, which includes the major changeset and Changesets beta-mode state.
2. CI opens a separate **Version Packages** PR containing `1.0.0-beta.0`, package changelogs and matching Rust workspace/lockfile versions. Review and merge that version PR.
3. Approve **Prepare native release assets** for that exact main commit and version. CI builds both architectures, validates notes/channel/source and publishes the native GitHub assets behind the release environment approval.
4. Rerun the normal **Release** workflow for the same version commit after those assets exist. Changesets publishes to npm's `beta` dist-tag. Native image publication has its own explicit approval; deployment remains separate.

Until native assets are prepared, the npm workflow deliberately stops at its asset gate. It does not publish a launcher without its matching executables. The channel guard rejects prerelease versions without matching beta-mode state and checks that both existing public packages retain a stable npm `latest` line before beta publication.

New changesets produce later `-beta.1`, `-beta.2` versions through subsequent version PRs. To promote, prepare a reviewed change using `pnpm changeset pre exit`, let the version workflow produce stable `1.0.0` and repeat the approved artifact/publication sequence. The stable publication updates `latest`. The current workflows operate on `main`; maintaining stable fixes during the beta series requires a separately configured maintenance/release branch.
