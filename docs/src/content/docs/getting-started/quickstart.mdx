---
title: Quick Start
description: Run the native daemon and take over a stopped official profile.
---

Install an exact published native release on Linux x64/ARM64 with glibc 2.36+ and Node 24.16+:

```bash
npm install -g @agent-wechat/cli@VERSION
wx --json version
wx config show
wx serve
```

Replace `VERSION` with the intended release. The npm installer verifies the matching executable against hashes bundled in the package. Direct executable installation needs no Node; see [installation](/getting-started/cli/installation/). Incoming WXGF previews and audio/video source preparation additionally need FFmpeg/FFprobe, included in the runtime image.

`serve` runs in the foreground, binds loopback and creates private credentials/sidecars under the configured data directory. It neither starts Docker nor creates a QR automatically. In a second terminal:

```bash
# Close the official app and preserve a backup before takeover.
wx auth login --official
# Select a specific complete profile on the daemon host when necessary:
# wx auth login --official=/absolute/official-home
wx accounts list
wx threads
wx messages list filehelper
```

The saved username/UIN/device/key information must match the profile. Saved trust is tried when available; WeChat may require phone approval or a fresh white QR. History becomes readable only after the accepted credentials unlock every selected database. With multiple accounts, pass `--account ACCOUNT_ID`.

The official profile stays at its selected path. Native settings default to `~/.config/agent-wechat/server/config.toml`; additional data defaults to `~/.local/share/agent-wechat`. [Storage](/operations/data/) explains overrides and backups. For a background owner, use `wx daemon start` and `wx daemon stop`; do not run foreground, systemd, Compose and OpenClaw owners for the same profile simultaneously.

Reading history does not send messages or mark them read. See the [CLI reference](/getting-started/cli/commands/) for deliberate sends, media jobs and explicit local reads.
