---
title: Identify contacts and threads
description: Read saved account categories and work-contact labels through wx or the API.
---

import { Aside } from '@astrojs/starlight/components';

Contact, thread, group and member responses include `classification`, derived from
the account's saved WeChat profile. It describes the peer independently of the
thread's `kind` and the contact's `relation`.

1. List contacts or inspect a known username:

   ```bash
   wx --json contacts list --limit 20
   wx --json contacts get gh_example
   ```

2. Read the classification in the returned item:

   ```json
   {
     "id": "gh_example",
     "relation": "unknown",
     "classification": {
       "category": "business",
       "namespace": "wechat",
       "businessType": 1,
       "businessKind": "service_account",
       "openIm": null
     }
   }
   ```

The same data is available through `GET /v1/accounts/{account}/contacts/{username}`,
thread reads, group reads and member reads. SDK methods such as
`client.contact(accountId, username)` return it directly. Older servers may omit
the field.

| Category | Meaning |
| --- | --- |
| `business` | Saved official/business account metadata. |
| `openim` | A WeCom contact identity. |
| `openim_customer_service` | The separate OpenIM customer-service identity family. |
| `group` | A recognized group identity. |
| `system` | A recognized built-in WeChat peer, such as File Transfer. |
| `unknown` | The available evidence does not establish another category. |

`businessType` preserves WeChat's saved numeric value. `businessKind` gives the
verified label: `official_account`, `service_account`, `enterprise`,
`enterprise_child` or `photo_account`. Unknown or conflicting values produce
`null`. An Official Account label does not establish that it is a subscription
account.

For OpenIM contacts, `openIm` includes saved `appId`, `wordingId`, localized
`wordings` and application/account-type references. Each wording keeps its
`languageId` and `text`; the caller chooses a language. These are cached display
labels, rather than a guarantee of employment or account permissions.

<Aside title="Good to know">
- `unknown` does not mean a personal account, nonfriend or unavailable account.
  The contact's `relation` remains separate.
- `namespace` distinguishes ordinary WeChat, OpenIM, customer service and other
  recognized identifier families. It does not grant additional operations.
- Reads do not refresh contacts. Missing OpenIM labels remain missing; downloading
  the separate OpenIM resource catalogs is not implemented.
- Existing thread `kind` values and message-routing policies are unchanged.
</Aside>
