---
title: Native HTTP API
description: Account-scoped v1 resources, jobs, events and media.
---

The native API is versioned under `/v1`. Except the minimal `/health` liveness endpoint, requests require bearer authentication and appropriate account scopes. Use lossless decimal-string IDs and opaque server-issued cursors. The Rust contracts generate the private TypeScript SDK; a route alone is not evidence of a successful network operation.

| Surface | Routes / behavior |
| --- | --- |
| Runtime/account status | `GET /v1/status`, `GET /v1/accounts`, `GET /v1/accounts/{account}`, account `/capabilities` |
| Official profile selection | `POST /v1/profiles/official`; prepares in-place identity-bound ownership before login |
| Login | Account `POST /login-attempts`, `GET /login-attempts/{id}`, `GET /login-attempts/{id}/qr`, `POST /login-attempts/{id}/cancel` |
| Lifecycle | Account `POST /connect`, `/disconnect`, `/logout`, `/forget-credentials`; persistent logout/forget fences |
| Catalog/history | Account `GET /threads`, `/contacts`, `/groups`, `/groups/{id}/members`, `/threads/{id}/messages`, `/messages`, `/messages/{id}` |
| Quote resolution | Account `GET /messages/{id}/quote`; parent-bound local original lookup and embedded-content fallback |
| Exact metadata | Account `POST /contacts/lookup`, `GET /groups/{id}/lookup`; refresh/sync operations retain their own checkpoints |
| Sends | Account `POST /sends`, `GET /sends/{id}`, `GET /sends/by-idempotency-key`, `POST /sends/{id}/cancel` |
| Media | Account `POST /uploads`, message `GET /media`, `POST /media-transfers`, asset `GET /media/{id}/content` |
| Durable jobs | Account `GET /jobs/{id}`, `POST /jobs/{id}/cancel`, `/retry`, `POST /media-writeback/repair` |
| Thread reads | Account `POST /threads/{id}/read-state` with only `expectedVersion`; clears the whole thread through a frozen boundary and reports its native cross-device notification outcome |
| Events | Account `GET /events`, `GET /events/stream`, `POST /consumers/{consumer}/ack` |
| Access tokens | `GET/POST /v1/access-tokens`, `DELETE /v1/access-tokens/{id}`; owner/admin permissions |

Paths containing placeholders must be URL encoded. A send/upload/login response retains a durable identity before asynchronous work; use idempotency and inspect the same resource after a lost response. `needs_review`, partial voice receipts and confirmed expiry must not trigger blind retries. Native acceptance does not prove recipient delivery/playback.

Media separates advertised variants from verified cached bytes and returns pending/expired/unsupported states explicitly. Cached content supports bounded byte ranges and integrity/length checks. Cached bytes can outlive remote expiry. HTTP cancellation closes streaming without cancelling already submitted jobs.

Resource cursors bind the account, query and retained view; an expired cursor requires an explicit new view. Tombstones preserve deleted positions. SSE supports journal replay, bounded retention and gap reporting. Persist custody before acknowledgement. Consumer acknowledgements never change unread state; whole-thread marking reports a native cross-device read boundary.

`GET /v1/accounts/{account}/messages?query=project&limit=20` searches locally stored messages across all threads with account `read` permission. `query` (also accepted as `search`) is a case-insensitive substring, at most 256 UTF-8 bytes. `limit` is 1–200 (default 50); pass the returned opaque `nextCursor` with the same query to continue. The response is a message page with `items`, `nextCursor`, `sourceGeneration` and `coverage`. Retained views keep message order and thread identity across edits, name-map changes, deletion tombstones and new arrivals. Views expire after 30 minutes and are bounded to 100,000 source messages and 32 MiB of normalized source rows; exceeding capacity returns an explicit error. This read neither downloads media nor changes unread state and does not fetch remote history. Use the existing `/threads/{id}/messages` route to restrict a query to one thread.

`GET /v1/accounts/{account}/messages/{id}/quote` requires account `read` scope. The stored parent determines the conversation; there is no caller-selected thread/server ID. It returns `{ accountId, messageId, threadId, state, message, embeddedText?, embeddedImage?, senderId? }`. States are `resolved` (a normalized original text/image), `embedded` (original absent, quote carries text or image metadata), `missing`, `ambiguous`, `invalid` or `unsupported`. `message` is null except when resolved. Embedded image metadata itself is never returned; `embeddedImage` signals that the parent quote has an image descriptor. Retrieve/download it through the existing parent message `/media` and `/media-transfers` routes. Quote-owned media has `officialWriteback: "unsupported"`; its verified bytes stay in the daemon sidecar.

Normalized messages add optional `appMessageType` and `quote: { serverId, type }`. A quote's `body` is the current sender's comment. Forwarded bundles expose bounded rendered history in `body`. Message lists/search do not resolve quotes or download media; follow the parent quote endpoint explicitly.

See the [CLI workflows](/getting-started/cli/commands/) and public source contracts in [`wechat-api`](https://github.com/thisnick/agent-wechat/tree/main/packages/native-client-rust/crates/wechat-api). The old container `/api` and UI operations are removed.
