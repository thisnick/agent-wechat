---
title: Native HTTP API
description: Account-scoped v1 resources, jobs, events and media.
---

The native API is versioned under `/v1`. Except the minimal `/health` liveness endpoint, requests require bearer authentication and appropriate account scopes. Use lossless decimal-string IDs and opaque server-issued cursors. The Rust contracts generate the private TypeScript SDK; a route alone is not evidence of a successful network operation.

| Surface | Routes / behavior |
| --- | --- |
| Runtime/account status | `GET /v1/status`, `GET /v1/accounts`, `GET /v1/accounts/{account}`, account `/capabilities` |
| Official profile selection | `POST /v1/profiles/official`; prepares in-place identity-bound ownership before login |
| Login | Account `POST /login-attempts`, `GET /login-attempts/{id}`, `GET /login-attempts/{id}/qr`, `POST /login-attempts/{id}/cancel` |
| Lifecycle | Account `POST /connect`, `/disconnect`, `/logout`, `/forget-credentials`; persistent logout/forget fences |
| Catalog/history | Account `GET /threads`, `/contacts`, `/groups`, `/groups/{id}/members`, `/threads/{id}/messages`, `/messages`, `/messages/{id}` |
| Quote resolution | Account `GET /messages/{id}/quote`; parent-bound local original lookup and embedded-content fallback |
| Exact metadata | Account `POST /contacts/lookup`, `GET /groups/{id}/lookup`; refresh/sync operations retain their own checkpoints |
| Sends | Account `POST /sends`, `GET /sends/{id}`, `GET /sends/by-idempotency-key`, `POST /sends/{id}/cancel` |
| Message recalls | Account `POST /messages/{id}/recall`; durable own-message operation, inspected with `GET /operations/{id}` |
| Media | Account `POST /uploads`, message `GET /media`, `POST /media-transfers`, asset `GET /media/{id}/content` |
| Durable jobs | Account `GET /jobs/{id}`, `POST /jobs/{id}/cancel`, `/retry`, `POST /media-writeback/repair` |
| Thread reads | Account `POST /threads/{id}/read-state` with only `expectedVersion`; clears the whole thread through a frozen boundary and reports its native cross-device notification outcome |
| Events | Account `GET /events`, `GET /events/stream`, `POST /consumers/{consumer}/ack` |
| Access tokens | `GET/POST /v1/access-tokens`, `DELETE /v1/access-tokens/{id}`; owner/admin permissions |

Paths containing placeholders must be URL encoded. A send/upload/login response retains a durable identity before asynchronous work; use idempotency and inspect the same resource after a lost response. `needs_review`, partial voice receipts and confirmed expiry must not trigger blind retries. Native acceptance does not prove recipient delivery/playback.

Media separates advertised variants from verified cached bytes and returns pending/expired/unsupported states explicitly. Cached content supports bounded byte ranges and integrity/length checks. Cached bytes can outlive remote expiry. HTTP cancellation closes streaming without cancelling already submitted jobs.

The daemon validates image framing and decodes the image before making an asset available. Complete JPEGs can include data after their end-of-image marker; that data is retained in the served bytes and official-profile DAT writeback. This image trailer is inside the decoded payload, separate from the DAT wrapper's 15-byte header and AES padding. Profile encryption, paths and resource records use the existing supported official format.

Image boundaries are format-specific: JPEG uses its parsed end marker, PNG its complete `IEND` chunk, GIF its parsed stream trailer, and WebP its declared RIFF length. Bytes beyond those boundaries remain part of the verified source; they are never stripped from the asset. Static WebP images decode as a single image, while GIF and animated WebP retain their frames within decoding limits. Supporting appended source data does not imply that WeChat adds the same trailer to each format.

The native image decoder supports JPEG, PNG, GIF, WebP and the observed v2 WXGF container. WXGF sources remain `image/x-wxgf`; the daemon creates a separately encrypted JPEG still preview using FFmpeg. `MediaAsset.preview` supplies the preview's `contentType`, `byteLength`, `sha256`, `filename`, `contentUrl` and `sourceSha256`. The ordinary content endpoint always serves the unchanged source. Request `GET /v1/accounts/{account}/media/{asset}/content?representation=preview` for the still; its ETag/ranges describe the preview and `X-Source-Sha256` binds it to the original. The same account `media` permission applies. Cached previews survive restart and do not require another remote download. WXGF source animation frame counts, timing and transparency are not established; `animationFrames` remains null for that source. No source bytes are replaced with a preview in the official profile.

Video validation checks the MP4 signature and retains all source bytes, including metadata boxes; it does not fully decode the video. Ordinary file attachments, including PDFs, retain their bytes and use the file transfer's integrity checks. Image end-marker checks do not apply to video or files. Fixed validation reasons such as `image_decode_failed`, `image_decode_limit`, `jpeg_trailer_missing` and `png_trailer_missing` distinguish image validation from transport failures without exposing private metadata.

Incoming file messages support the observed attachment `encryver` values `0` and `1` through the same AES-keyed CDN transfer, with advertised size and checksum checks retained. Unknown versions or missing transport metadata report `unsupported_attachment_encryption` or `unsupported_attachment_transport`; these are media limitations rather than profile/schema errors. Separate unsupported app-message cards do not prevent retrieval of a valid file message.

Resource cursors bind the account, query and retained view; an expired cursor requires an explicit new view. Tombstones preserve deleted positions. SSE supports journal replay, bounded retention and gap reporting. Persist custody before acknowledgement. Consumer acknowledgements never change unread state; whole-thread marking reports a native cross-device read boundary.

`GET /v1/accounts/{account}/messages?query=project&limit=20` searches locally stored messages across all threads with account `read` permission. `query` (also accepted as `search`) is a case-insensitive substring, at most 256 UTF-8 bytes. `limit` is 1–200 (default 50); pass the returned opaque `nextCursor` with the same query to continue. The response is a message page with `items`, `nextCursor`, `sourceGeneration` and `coverage`. Retained views keep message order and thread identity across edits, name-map changes, deletion tombstones and new arrivals. Views expire after 30 minutes and are bounded to 100,000 source messages and 32 MiB of normalized source rows; exceeding capacity returns an explicit error. This read neither downloads media nor changes unread state and does not fetch remote history. Use the existing `/threads/{id}/messages` route to restrict a query to one thread.

`GET /v1/accounts/{account}/messages/{id}/quote` requires account `read` scope. The stored parent determines the conversation; there is no caller-selected thread/server ID. It returns `{ accountId, messageId, threadId, state, message, embeddedText?, embeddedImage?, senderId? }`. States are `resolved` (a normalized original text/image), `embedded` (original absent, quote carries text or image metadata), `missing`, `ambiguous`, `invalid` or `unsupported`. `message` is null except when resolved. Embedded image metadata itself is never returned; `embeddedImage` signals that the parent quote has an image descriptor. Retrieve/download it through the existing parent message `/media` and `/media-transfers` routes. Quote-owned media has `officialWriteback: "unsupported"`; its verified bytes stay in the daemon sidecar.

Normalized messages add optional `appMessageType` and `quote: { serverId, type }`. A quote's `body` is the current sender's comment. Forwarded bundles expose bounded rendered history in `body`. Message lists/search do not resolve quotes or download media; follow the parent quote endpoint explicitly.

## URL shares

Received shared cards (`49/3`, `49/4`, `49/5`) add `link: { title, description, url, sourceName }` and readable `body` text. Each metadata field can be null. Private thumbnail URLs, CDN IDs and encryption keys are excluded. Retrieve an advertised preview with the parent message's `/media` and `/media-transfers` routes and quality `thumbnail`. It is an image asset with `officialWriteback: "unsupported"`; the card remains type49. Thumbnail retrieval supports complete encrypted CDN descriptors or public HTTP(S) `thumburl`, with an 8 MiB bound, pinned public DNS, no redirects and image decoding. The target article URL is never fetched. Unavailable thumbnails do not remove metadata.

`POST /v1/accounts/{account}/sends` accepts this new `share` kind, requires account `send` scope and an `Idempotency-Key` header:

```json
{
  "kind": "share",
  "threadId": "RECIPIENT_OR_GROUP_ID",
  "title": "An explicit title",
  "url": "https://example.com/article",
  "description": "Optional description",
  "thumbnailUrl": "https://example.com/preview.jpg"
}
```

Title and description are limited to 16 KiB each; URLs to 8 KiB each. `description` and `thumbnailUrl` are optional. The daemon composes escaped app subtype5 metadata and submits it once through the app-message route. It does not fetch webpage metadata or upload thumbnail bytes. The response is a normal durable send intent, inspected/cancelled through `/sends`; an uncertain or interrupted submission becomes `needs_review`. Reusing a key with changed metadata conflicts. Accepted receipts project an outgoing type49/subtype5 history row through the supported profile writer. Existing text payloads remain valid.

Live server acceptance, recipient previews and official-client rendering of the new send type remain unverified.

## Message recalls

`POST /v1/accounts/{account}/messages/{id}/recall` requires account `send` scope,
an `Idempotency-Key` header and `{ "serverId": "18446744073709551615" }`.
Use the original message's opaque `id` and exact decimal-string `serverId` from
history or a verified send receipt. The daemon resolves the conversation and
checks that the stored message was sent by the account. A numeric JSON server
ID, missing identity, provisional send or mismatched target cannot authorize a
recall.

The response is HTTP 202 with an operation of kind `message_recall`. Inspect
`GET /v1/accounts/{account}/operations/{operationId}` with the same account's
`send` scope. Successful results have state `succeeded` and status `recalled` or
`already_recalled`. Definitive refusal is `failed`; an uncertain remote outcome
is `needs_review`. Results retain the target IDs, `remoteOutcome`, `serviceCode`
and `profileProjection`. An accepted remote reply with pending local repair
does not authorize another network request. Reusing the same key/target returns
the retained operation; another key cannot bypass its target claim. Operations
cannot be cancelled after submission; DELETE returns HTTP 409
`operation_cannot_cancel`. Closing the request or stopping a watcher leaves
server-owned work running. WeChat determines whether a message remains eligible.
Target claims belong to one canonical registered account; independent profile
copies and separate daemons do not share them.

Recalls observed from another party or another device use the same durable
marker as confirmed outgoing recalls. Reads preserve the target's IDs and order,
return `type: 10000`, `body: "[Message recalled]"`, empty media/mentions and
optional `recall: { observedAt, recalledAt? }`. A zero or unknown native recall
time is omitted. Each account/thread/server identity emits one
`message.recalled` event with `threadId`, `serverId`, `observedAt`, optional
`messageId`/`recalledAt`, and `origin`; the target may arrive after its recall.
This control does not create a new ordinary incoming message.

Recalled media returns HTTP 410 `message_recalled`, including previously cached
assets. Quote resolution returns state `recalled` with `message: null` when the
parent or quoted target is recalled; it does not fall back to embedded original
content. These results are terminal. Storage retention and backup boundaries are
described in [Data and Storage](../../operations/data/).

An old unbound attachment handle returns HTTP 409 `media_identity_unavailable`;
a handle whose nonrecalled source changed returns HTTP 409 `media_source_changed`.
Both are terminal for that handle. Rediscover the message's media to obtain its
current source-bound handle; do not retry the old transfer indefinitely.

See the [CLI workflows](/getting-started/cli/commands/) and public source contracts in [`wechat-api`](https://github.com/thisnick/agent-wechat/tree/main/packages/native-client-rust/crates/wechat-api). The old container `/api` and UI operations are removed.
