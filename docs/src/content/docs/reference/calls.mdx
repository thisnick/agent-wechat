title: Calling

Use `wx` to make direct or conference voice and video calls with this computer's
microphone, speakers and camera, or drive headless calls with `wx calls session`
for scripts and automation. OpenClaw setup (voice-only) is in
[Set up calling](/openclaw/calling/).

## Check availability

1. Select your daemon and account, then run `wx calls status`. Accounts without
   a current authenticated session report `capabilities: {}`. Require the
   advertised capability for the operation you want (`directAudio`,
   `directVideo`, `conferenceAudio`, `conferenceVideo`).
2. Run `wx calls devices` to list local microphones, speakers and cameras.
3. Start or answer a call below. Keep the owning terminal open until cleanup
   finishes; a second client cannot take over.

## Direct calls and monitoring

| Command | Behavior |
| --- | --- |
| `wx calls monitor --json` | Observe events without opening audio or camera devices |
| `wx calls monitor` | Wait for invitations; open audio (and camera on video calls) when you accept |
| `wx calls dial CONTACT` | Start a direct voice call using local microphone and speakers |
| `wx calls dial CONTACT --video` | Start a direct video call with camera capture and terminal video preview |
| `wx calls answer [CALL_ID]` | Answer the current matching voice or video offer |

Pass `--camera <source>` to choose a camera (`auto`, `off`, `test` for an
animated FFmpeg test pattern, `file:<path>` to loop a media file, or a device
path/name), `--camera-off` to join a video call without sending camera video,
and `--muted` to start muted.

The monitor shows direct offers after the daemon acknowledges ringing. For a
conference invitation, enter `j NUMBER`. Leaving returns to watching; standalone
start/join exits. JSON monitoring never answers or joins automatically.

## Conference calls

1. Require `conferenceCreate` and `conferenceAudio` to start, or
   `conferenceJoin` and `conferenceAudio` to join. Add `conferenceVideo` for
   `--video`.
2. Start in an existing group with contact IDs:

   ```sh
   wx calls conference start GROUP_ID --invite CONTACT_A --invite CONTACT_B
   wx calls conference start GROUP_ID --invite CONTACT_A --video
   ```

   Or join a current invitation:

   ```sh
   wx calls conference join GROUP_ID
   ```

   No current invitation means join fails; it never creates a room.
3. Speak after connection. Incoming audio tracks are mixed for playback, and
   incoming video tracks render in the terminal:

   ```text
   Connected. Audio tracks: 1, video tracks: 1.
   ```

## Audio, video and in-call controls

Run `wx calls devices` first, then select endpoints with
`wx calls dial CONTACT --input-device INPUT_ID --output-device OUTPUT_ID`.
Without those options, OS defaults are used. Linux accepts PulseAudio or
PipeWire-Pulse names, Windows accepts endpoint IDs, and macOS accepts the
numeric CoreAudio device IDs shown by `wx calls devices` (custom macOS devices
bypass system voice processing and run without echo cancellation).
`wx calls devices` also lists local cameras on Linux (V4L2), macOS
(`avfoundation`), and Windows (`dshow`).

Interactive calls show the controls, meters and (when video is active) a 24-bit
TrueColor terminal video preview. Press Enter after a key; `l` or `h` leaves the
call and returns to watching in `monitor`. Ctrl-C leaves and exits the command
after a short cleanup wait.

```text
m + Enter    Microphone          v + Enter    Camera (video calls)
s + Enter    Speaker             i + Enter    Invite
p + Enter    Participants        d + Enter    Devices
l/h + Enter  Leave call          ? + Enter    Help
Ctrl-C       Leave and exit
Mic [#######...] -18dB  Speaker [########..] -10dB
Alice [######....] -24dB joined mic on cam on
Bob   [..........] -60dB joined mic off
>
```

Bars measure digital PCM; `0 dB` is full scale and `!` marks a recent near-clipping
peak. Mic measures outgoing signal; Speaker measures mixed playback, not hardware
volume. Participant meters measure each source before mixing, even with playback
off. Silence does not prove mute or departure. Unattributed sources use track
labels. Meters and terminal video stay out of JSON and redirected output; `p`
shows the full roster.

Use `i` to search contacts or enter `invite CONTACT_ID OTHER_ID`. Submission does
not mean someone joined. Invite works only in conferences; it cannot promote a
direct call. After `d`, use `d input NUMBER`, `d output NUMBER` or `d default`.
Device preparation leaves current audio running, but switching can briefly
interrupt it. Enter `cancel` to close a picker.

Use the [Calls API](../calls-api/) and [media reference](../calls-media/) for
authentication, ownership, binary `WXCM` audio/video frames and codec
negotiation.

## Headless sessions for automation

`wx calls session` runs a call client in the background (or in the foreground
with `--stdio`) without a terminal screen or real audio and camera hardware.
Start one session per account, drive it with sequential commands, wait on
events or media thresholds, and inspect recordings or snapshots.

| Command | Behavior |
| --- | --- |
| `wx calls session start --name NAME --ready` | Start a background session with synthetic audio (`--audio`) and video (`--video`) |
| `wx calls session dial --session NAME CONTACT [--video]` | Place a direct voice or video call |
| `wx calls session answer / reject / hangup --session NAME` | Answer or reject an incoming offer, or hang up the active call |
| `wx calls session conference start / join / invite` | Start, join, or invite contacts into a group conference |
| `wx calls session mute / unmute / camera on\|off` | Toggle local microphone or camera and notify the other side |
| `wx calls session audio SOURCE` / `video SOURCE` | Switch outgoing audio or video live mid-call |
| `wx calls session wait --session NAME [FILTERS]` | Block until an event (`--event`, `--state`, `--peer-status`, `--control-kind`, `--participant`) or media metric (`--audio-frames`, `--dominant-hz`, `--video-frames`) matches |
| `wx calls session status / events / snapshot / record` | Inspect state, read NDJSON events, save decoded JPEG/PNG frames, or record WAV/video |
| `wx calls session stop NAME` | Hang up any active call, finalize recordings and exit |

Synthetic sources need no microphone, speaker or camera:

- **Audio (`--audio`)**: `silence` (default), `tone[:HZ[:AMP[:ON_MS:OFF_MS]]]` (pure sine or pulsed tone), `file:PATH[:loop|:once]`, or `device[:ID]`.
- **Output (`--output`)**: `null` (default; meters and records without opening speakers) or `device[:ID]`.
- **Video (`--video`)**: `test` (animated `testsrc2`, default), `smpte` (color bars), `color:NAME|#RRGGBB`, `file:PATH`, `off`, `auto`, or a device path.

```sh
wx --account alice calls session start --name alice --audio tone:440 --video test --record-dir /tmp/alice-rec --json
wx --account bob calls session start --name bob --ready --audio tone:880 --video color:green --json

wx calls session dial --session alice wxid_bob --video --json
wx calls session wait --session bob --event call.offered --json
wx calls session wait --session alice --peer-status acknowledged --json
wx calls session answer --session bob --json

wx calls session wait --session bob --audio-frames 20 --dominant-hz 440 --video-frames 5 --json
wx calls session snapshot --session bob --out /tmp/bob-frame.jpg --json
wx calls session hangup --session alice --json
wx calls session stop alice && wx calls session stop bob
```

:::note[Good to know]
This build limits native calls to 20 minutes; longer calls still need validation.
Direct-call promotion and screen sharing are unavailable. Leaving ends our
participation, not the room. Inspect an uncertain end before another call.

Outgoing camera capture and daemon-side video transcoding require `ffmpeg` on
`PATH` (or `WX_FFMPEG_BIN`) with HEVC (`hevc`/`libx265`), H.264
(`h264`/`libx264`) or MJPEG codecs. The CLI displays received video using
standalone JPEG frames and rotates frames locally when the peer changes
orientation.

The legacy WeChat relay can reuse an audio nonce across senders. The daemon
continues the call for compatibility, which weakens audio confidentiality and
integrity.

Source and release builds include audio support; see [build prerequisites](../build/#included-features).
Linux local audio needs `libpulse0` and PulseAudio or PipeWire-Pulse. The daemon,
help and JSON monitoring need no local devices or sound server. `wx calls --help`
does not connect or log in.

`WX_CALL_DEBUG=1 wx calls monitor` prints timestamped events without the media
owner token, first-frame submission and WebSocket close details to stderr.
:::
