title: Calling
description: Call availability, client ownership and CLI/OpenClaw participation.
---

Check calling availability with `wx calls status`, then use the CLI, OpenClaw or
the [control](../calls-api/) and [media](../calls-media/) APIs.
Direct and conference voice use the same control and media APIs. Check the
daemon's advertised capabilities before participating. Video and direct-call
promotion are unavailable.

## Check availability

1. In a source build, run `wx calls --help`. The parent command only prints help;
   it does not connect, log in or open audio devices.
2. Run `wx calls status` against your selected daemon. Normal startup includes
   the native call backend. Accounts without a current authenticated session
   report empty `capabilities: {}`.
3. Require the corresponding capability before participating. An API route or a
   configured plugin does not make a call available.

Normal source and release builds include calling and local audio support;
[Build from source](../build/#included-features) lists the prerequisites.
A headless daemon does not open a microphone or speaker. Runtime account
permissions and advertised capabilities determine whether a client may participate.

Use the [Calls API](../calls-api/) and [media reference](../calls-media/) for
authentication, ownership, protocol versions and PCM payloads. Keep the owning
client connected until cleanup finishes. An uncertain end needs inspection
before another call.

## CLI and OpenClaw

| Command | Behavior |
| --- | --- |
| `wx calls devices` | List local microphone/speaker IDs without connecting to a daemon or starting audio |
| `wx calls monitor --json` | Observe events without opening audio devices |
| `wx calls monitor` | Show “Waiting for calls. Ctrl-C exits.” until a call comes in. Open audio on acceptance. |
| `wx calls dial CONTACT` | Participate using this computer's microphone and speakers |
| `wx calls answer [CALL_ID]` | Answer the current matching offer using local audio |

Release executables include local audio support. The monitor shows the incoming
prompt after the daemon acknowledges ringing. Accepting stays tied to the
selected call, even if another call arrives later.

Run `wx calls devices` first, then select endpoints with
`wx calls dial CONTACT --input-device INPUT_ID --output-device OUTPUT_ID`.
Without those options, the OS defaults are used. Linux accepts PulseAudio or
PipeWire-Pulse names; Windows accepts endpoint IDs. On macOS, select the defaults
in System Settings; custom endpoint IDs are not supported by the current adapter.

Interactive calls show the controls and meters below. Press Enter after a key;
Ctrl-C leaves the call and waits briefly for cleanup.

```text
m  Microphone    s  Speaker    i  Invite
p  Participants  d  Devices    l/h  Leave    ?  Help
Mic [#######...] -18dB  Speaker [########..] -10dB
Alice [######....] -24dB joined mic on
Bob   [..........] -60dB joined mic off
>
```

The bars rise with louder audio and fall toward silence. `0 dB` is digital full
scale; `!` marks a recent peak near clipping. A muted microphone shows no outgoing
signal. The speaker meter measures audio sent to playback, not the hardware
volume setting or sound in the room. Each receive participant has a separate
level before playback mixing. A quiet meter does not imply mute or departure.
Unattributed sources are labeled by track. Meters stay out of JSON and redirected
output.

See [Conference calls](../conference-calls/) for start/join, invitations,
participant levels and in-call device controls.

Run `WX_CALL_DEBUG=1 wx calls monitor` to print a timestamped trace to stderr
while using the call controls. It shows incoming call events with the media
owner token removed, whether the first audio frame was written to the socket,
and any WebSocket close code or reason the CLI received.

Configure independent voice/video permissions, realtime speech models, OpenAI
credentials and consultation in [Set up calling](/openclaw/calling/).

:::note[Good to know]
This build limits native calls to 20 minutes; longer calls still need validation.

The legacy WeChat relay can reuse an audio nonce across senders. The daemon
continues the call for compatibility, which weakens audio confidentiality and
integrity.

Linux CLI audio needs `libpulse0` and a working PulseAudio or PipeWire-Pulse
service. The headless image includes the client library but does not need audio
devices or a sound server to run the daemon.
:::
