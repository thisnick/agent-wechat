Use one control WebSocket to observe and control calls. Only its winning owner
can attach media. See [media framing](../calls-media/) for audio transport and
[calling architecture](../calls-architecture/) for package responsibilities.

## Connect

All routes require an account-authorized bearer token with the `calls` scope.
Use the header on HTTP requests and WebSocket upgrades; never put tokens in URLs.
Replace `{account}` and `{callId}` with URL-encoded identifiers.

| Method | Path | Result |
| --- | --- | --- |
| GET | `/v1/accounts/{account}/calls/current` | JSON snapshot |
| WebSocket | `/v1/accounts/{account}/calls/socket` | JSON commands and events |
| WebSocket | `/v1/accounts/{account}/calls/{callId}/media` | Owner-only media |

1. Inspect the snapshot:

   ```bash
   curl -sS -H "Authorization: Bearer $TOKEN" \
     "$BASE/v1/accounts/$ACCOUNT/calls/current"
   ```

   Example with an enabled direct-voice backend and no active call:

   ```json
   {
     "capabilities": {"directAudio":true,"directVideo":false,"conferenceAudio":false,"conferenceVideo":false},
     "availability": {"busy":false,"ownedByThisClient":false},
     "currentOffer": null,
     "currentPendingOffer": null,
     "currentCall": null,
     "audioFormat": {"sampleRate":16000,"channels":1,"frameMs":20}
   }
   ```

2. Open the control socket. Its first `hello` event contains that snapshot plus
   `protocolVersion: 1` and the connection's `clientId`. Prepare audio, then send:

   ```json
   {"type":"call.ready","requestId":"ready-1","ready":true,"format":{"sampleRate":16000,"channels":1,"frameMs":20},"scope":{"kind":"outgoing"}}
   ```

3. Initiate a voice call:

   ```json
   {"type":"call.dial","requestId":"dial-1","target":{"kind":"direct","contactId":"example-contact"},"callType":"voice"}
   ```

   A successful claim returns:

   ```json
   {"type":"command.result","requestId":"dial-1","status":"accepted","callId":"example-call","ownerToken":"<secret owner token>","code":null}
   ```

   Preserve the token privately for media attachment. Acceptance starts the
   operation; wait for `call.state` with `state: "connected"` before sending audio.

## Incoming calls and snapshots

A `call.pending` event contains `offer` with phase `waiting_for_ready` or
`preparing`; `offer: null` clears it. Pending calls cannot be answered yet. Scope
readiness to that offer using `{"kind":"offer","callId":"example-call","expectedRevision":1}`.
An omitted readiness scope means `{"kind":"all"}`. Setting `ready: false` clears readiness.

Audio format is announced in `audioFormat` and each track's `format`.

An actionable incoming event looks like:

```json
{"type":"call.offered","offer":{"callId":"example-call","revision":1,"kind":"direct","callType":"voice","callerId":"example-contact"}}
```

Answer using its current revision:

```json
{"type":"call.answer","requestId":"answer-1","callId":"example-call","expectedRevision":1}
```

The first successful answer owns the call. Other clients receive `already_claimed`.
Active `currentCall` and `call.state.call` share this shape:

```json
{"callId":"example-call","revision":2,"kind":"direct","callType":"voice","direction":"incoming","state":"connected","ownedByThisClient":false}
```

Same-account observers see this metadata without owner tokens or media access.
HTTP snapshots always report ownership as false: ownership belongs to a socket.
`availability.busy` also covers calls on other accounts, whose details stay hidden.

## Commands and events

Every command requires `type` and `requestId`. Reuse an ID only for an identical
command. End/answer/reject commands require the latest `expectedRevision`.

| Command | Additional fields |
| --- | --- |
| `call.ready` | `ready`, `format`, optional `scope` |
| `call.dial` | `target`, `callType` |
| `call.answer` | `callId`, `expectedRevision` |
| `call.reject`, `call.cancel`, `call.hangup` | `callId`, `expectedRevision` |
| `call.mute` | `callId`, `muted` |
| `call.clear_audio` | `callId` |

Use `reject` for an offer, `cancel` before pickup and `hangup` once connected.
Results use status `accepted`, `replayed` or `error`. Error `code` is one of
`invalid_request`, `busy`, `already_claimed`, `offer_expired`, `not_owner`,
`unsupported`, `media_not_ready`, `outcome_unknown`, `capacity`, `stale`, `forbidden`,
`closed`; successful results have `code: null`.

| Event | Payload |
| --- | --- |
| `hello` | Connection ID, version and snapshot fields |
| `command.result` | `requestId`, `status`, nullable `callId`, `ownerToken`, `code` |
| `call.offered`, `call.pending` | `offer` |
| `call.state` | `call` |
| `calls.availability` | `availability` |
| `track.added`, `track.updated` | `callId`, audio `track` |
| `media.ready` | `sendTrack`, `receiveTrack` |
| `call.error` | `code` |

States are `offered`, `dialing`, `ringing`, `connecting`, `connected`, `ending`,
`ended`, `uncertain`. Stop sending at `ending`; retain control until confirmation.
An uncertain outcome blocks another call until resolved.

:::note[Good to know]
Reconnecting does not reclaim ownership.
Control messages are limited to 16 KiB. Reply to server WebSocket Pings;
a connection silent for 45 seconds closes, followed by five seconds for owner cleanup.
`kind` is `direct` or `conference`; `callType` is `voice` or `video`.
Only direct voice is currently implemented. Conference targets
`{"kind":"conference","groupId":"example-group","invitees":["example-contact"]}`
and video requests are not supported by the current backend.
:::
