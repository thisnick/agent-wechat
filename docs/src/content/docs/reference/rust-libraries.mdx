Use these libraries without the daemon or an official executable. Applications
connecting to a running daemon can use the [HTTP API](/use/api/).

| Crate | Purpose |
| --- | --- |
| [wechat-protocol](https://docs.rs/wechat-protocol) | Authentication, transport, sync and message codecs |
| [wechat-profile](https://docs.rs/wechat-profile) | Profile keys, contacts, history, cached media and checked writers |
| [wechat-calls](https://docs.rs/wechat-calls) | Voice-session/media building blocks, PCM mixing and optional Opus |
| [wechat-media](https://docs.rs/wechat-media) | Image inspection and decoding |
| [wechat-platform](https://docs.rs/wechat-platform) | Private files and OS support |

## Add dependencies

1. Choose the same published Rust library version for all libraries. Replace `VERSION`
   below with that version. `wechat-calls` and the account-owning client API first
   ship in the conference release; they are absent from older releases.

   ```bash
   cargo add wechat-protocol@=VERSION wechat-profile@=VERSION
   ```

2. Build with Rust 1.93.1+, a C compiler, Make and Perl. Cargo resolves supporting
   crates automatically. Native Opus also needs CMake and a C++ compiler.

From the release after 2.3.2, the Rust libraries have the same version number as
the CLI, daemon and OpenClaw plugin, and every release publishes all five. Earlier
library versions (up to 2.2.0) were numbered separately; choose a version listed
on crates.io.

## Read a stopped profile

Stop its writer or provide a consistent copy, then load the protected keys file.
The snapshot flag records your assertion; it does not stop another process.

```rust
use wechat_profile::{KeyFile, ListQuery, ProfileLocation, ProfileReader, ReadOptions};

fn contacts(profile: &str, keys_path: &str) -> wechat_profile::Result<()> {
    let reader = ProfileReader::open(
        ProfileLocation::new(profile)?, KeyFile::load(keys_path)?, ReadOptions {
            stopped_or_consistent_snapshot: true,
            ..Default::default()
        },
    )?;
    println!("{} contacts", reader.contacts(&ListQuery::default())?.items.len());
    Ok(())
}
```

Cached-media reads never initiate downloads. An application owning the profile
can use `OwnedReaderCache` with its own synchronization.

`contacts` lists current rows. Use `reader.contact(username)` for an exact stored
identity, including retained deleted contact or group rows. Check the returned
flags before changing a contact or group; a stored row alone does not make it eligible.

## Send one text message

Operations are methods on `NativeClient`. The application owns credential
storage, recovery and profile writeback.

1. Use `start_qr_login`, poll until `LoginStatus::Approved`, then call
   `complete_login`. Move the returned `AccountState` into
   `NativeClient::from_account(state, options)`. Cloned handles share one account
   owner. Operations no longer accept a separate mutable account state.
2. Record the operation, unique task ID and Unix-seconds timestamp before
   submitting. Use the recipient's exact WeChat username:

   ```rust
   use wechat_protocol::{wire, NativeClient, TextSendOptions, TextSendResult};

   async fn send_once(
       client: &NativeClient, recipient: &str, text: &str,
       task_id: &str, created_at: u32,
   ) -> anyhow::Result<TextSendResult> {
       let client_id = wire::client_message_id(task_id.as_bytes());
       anyhow::ensure!(client_id != 0, "Choose another task ID");
       client.send_text(recipient, text, TextSendOptions {
           created_at, client_message_id: client_id, source: None,
       }).await
   }
   ```

3. Check `accepted`, `returned_destination_matches` and
   `returned_client_id_matches`. The receipt's `server_message_id` does not prove
   recipient playback or history writeback.

From a checkout, the executable example displays a fresh login QR and submits once:

```bash
cargo run --manifest-path packages/native-client-rust/Cargo.toml -p wechat-protocol --example send_text -- RECIPIENT UNIQUE_TASK_ID "Hello from Rust"
```

Server acceptance prints `"accepted": true`. `--help` makes no network requests.
`qr_login`, `sync_once` and `protobuf` demonstrate login, one sync page and local
codecs. `sync_once` saves no cursor; persistent receivers must retain commands
before advancing it.

## Stickers

`wechat-media::prepare_sticker` prepares owned sources with optional fit/trim and
returns GIF, still and sampled-frame outputs. `sticker_export_gif` preserves
existing GIF bytes; `export_sticker_pack` writes one selected pack and a resumable
checksum index on the caller's filesystem.

`NativeClient` supplies Saved pages/metadata, bounded upload chunks, Saved
mutations, pack pages/details/captions and raw membership acknowledgements.
`StickerId::parse` normalizes a content identity; `StickerPackId::parse` keeps the
product identity separate. Applications using these transport methods own
submission journals and profile writeback. Cached profile reads never acquire
missing media.

Within this workspace, `wechat-core` provides `core.stickers(account)?`, an
account-bound asynchronous handle for `list`, `get`, `media`, `prepare`,
`add_prepared`, `save_received`, `move_after`, `remove`, `packs`, `browse`, `pack`,
`items`, `add_pack`, `remove_pack`, `acquire`, `acquire_pack`, `acquire_preview`, `send`, `sync` and
`job`. It owns account gating and uses existing jobs; filesystem export stays
outside that handle. `wechat-core` is the daemon implementation, not a separately
published HTTP client crate. External applications can use the
[sticker REST resources](/reference/stickers/).

## Send images and videos

Prepare and upload the copies before calling the protocol send method. Each method handles both qualities:

| Method | `upload.original: None` | `upload.original: Some(...)` |
| --- | --- | --- |
| `NativeClient::send_image` | Standard and thumbnail | Also includes the original image |
| `NativeClient::send_video` | Playback and thumbnail | Also includes the original video |

`UploadedImage.original` is now `Option<UploadedMedia>`. When migrating Rust callers, wrap an existing original in `Some(...)` and handle `None` when reading the field. Applications using the daemon's [media API](/use/quality/) select quality in the send request instead.

## Use calling media

Add `wechat-calls` at the same Rust library version. It opens no devices or Tokio
runtime. See its [crate guide](https://docs.rs/crate/wechat-calls/latest) for examples.

| Features | Use |
| --- | --- |
| Default `native-runtime` | Native session/media integration, protocol and Opus |
| No defaults + `native-opus` | Codec and PCM utilities without account dependencies |
| No defaults | Portable PCM, queues, pacing and mixing, including WebAssembly |

The high-level `client.calls()` facade is unfinished. Use the
[Calls API](../calls-api/) for complete call operations today.
[Crate architecture](../../how-it-works/rust-crates/) explains the dependencies.

## Profile writes

`stage_*` prepares bytes, `apply_*` applies logical updates, and `publish_*`
installs bytes at profile paths. These are API names, not official-client names;
`apply_*` and `publish_*` overlap and do not guarantee whole-operation atomicity.
MMKV staging produces encrypted data and matching `.crc` metadata. Publication
uses temporary files. `WriteOptions::durable_intent_id` refers to your saved
recovery record; the library cannot verify that record exists.

<Aside title="Good to know">
Account-owned async methods use transport workers. Blocking bootstrap methods
need a blocking worker in async applications. Fresh test logins may replace an
existing desktop session; examples retain credentials only in memory. Encrypt
saved credentials and investigate uncertain sends before retrying. Profile
writers require exclusive ownership, matching keys and supported schemas.
Linux profile support does not establish Windows/macOS compatibility. Some media
paths need FFmpeg. Pin versions and review API changes.
</Aside>
