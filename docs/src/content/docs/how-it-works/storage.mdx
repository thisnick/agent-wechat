title: Storage and backups
description: Where agent-wechat keeps its files, and what to back up.
---

```text
~/.config/agent-wechat/
├── server/config.toml              daemon settings (optional)
└── client.toml                     CLI: saved servers and default account
~/.local/share/agent-wechat/        data folder
├── api-token                       owner API token
└── accounts/<id>/
    ├── profile/                    WeChat profile: history, contacts, media
    └── agent/                      credentials, jobs, event log
$TMPDIR                             offline inspection snapshots
```

On Windows, settings live in `%APPDATA%\agent-wechat` and data in `%LOCALAPPDATA%\agent-wechat`. macOS uses the same paths as Linux.

If you logged in with `--official`, there's no `profile/` folder: the daemon uses WeChat for Linux's `~/xwechat_files` and `~/.xwechat` where they are, and keeps only its own files in the data folder.

## Back up

Stop the daemon (`wx daemon stop`, `systemctl --user stop agent-wechat-native` or `docker compose stop`), then copy the data folder:

```bash
tar -czf wechat-backup.tgz -C ~ .local/share/agent-wechat
```

With `--official`, add `xwechat_files .xwechat` to that command. The profile alone would lose queued sends, OpenClaw's progress and recall records; the data folder alone would have no history.

## Change locations

Set `dataDir` in `~/.config/agent-wechat/server/config.toml`, or pass `--data-dir`. See [Configuration](/reference/configuration/).

<Aside title="Good to know">
- **The running daemon reads its owned profile directly.** It reuses read-only database connections and short read transactions. Offline inspection uses private database copies (up to 2 GiB each, 8 GiB in total), so keep `$TMPDIR` on a disk with room, and never point it at the profile.
- **Unknown profile formats aren't touched.** The daemon checks each database's layout before writing, and stops if it doesn't recognize it. Back up and wait for an update rather than forcing it.
- **Damaged databases are kept.** If the daemon's own database fails a check, it keeps the original files and a recovery copy alongside.
- **Upgrading `wx` never deletes data.** Rolling back the binary doesn't undo data migrations, so keep a backup from before the upgrade.
- **Recall markers live in the data folder.** A profile export doesn't include them.
- OpenClaw keeps its own progress in `consumerStateDir`. Back that up too.
</Aside>
