| WeChat message | What you get | In OpenClaw |
| --- | --- | --- |
| Text | `body` | Message text |
| Image | Downloadable image, best quality available | Shown to the model |
| File (PDF, etc.) | Downloadable file | File path |
| Video | Downloadable MP4 | File path |
| Voice | Downloadable audio | File path, plus a transcript if configured |
| Animated sticker | Original sticker bytes | Image |
| Quote reply | Comment in `body`, plus the quote embedded in the reply | Comment and a labeled quote |
| Forwarded chat | Readable list of who said what | Same text |
| Link card (article, music, video) | Title, description, URL, source, optional thumbnail | Card text and thumbnail |
| Recalled message | `[Message recalled]` | Removed from pending work |
| Anything else | Marked unsupported | Not sent to the agent |

## Quotes

Incoming quotes use only the content carried inside the received reply. The normal message response includes it in `quote`, so OpenClaw renders text and link-card details without another quote request. A stored original never replaces the quoted excerpt. Local recall checks still suppress recalled content.

Images can be downloaded using metadata embedded in the quote. Missing or expired image data stays visible as a status alongside the comment. Quoted voice, video and files keep the comment and any supported summary, with an unavailable attachment status; their actual attachments aren't retrieved from a stored original.

`GET /messages/{id}/quote` remains available with the same URL and parameters. It returns a structured `message` marked `source: "embedded"`, with the quoted server ID, sender, type, readable body and image availability. This excerpt has no local message ID; image retrieval uses the parent reply ID. The response state is `embedded`, `missing`, `unsupported`, `invalid` or `recalled`; invalid or recalled quotes have `message: null`. It no longer returns a resolved original. See [Send quoted replies](/use/cli/#quoted-replies) for sending a reply that references a saved message.

## Forwarded chats

A forwarded chat bundle becomes plain text: each sender and message, with nested bundles indented. Images and files inside the bundle appear as placeholders and aren't downloaded.

## Link cards

You can send one with `wx messages send --share URL --title ...` or the `wechat_send_share` tool. You supply the title, description and thumbnail URL; nothing is fetched from the page.

## Recalls

When someone recalls a message, the daemon replaces its stored body with a recall notice, keeping its ID and position. Its media can no longer be fetched (HTTP 410), even if cached. You can recall your own messages with `wx messages recall` or the `wechat_recall` tool; WeChat decides whether a message is still recallable.

The API keeps `body` as `[Message recalled]` and reads `recall.replacementText` from the saved notice when available. It derives the original message's `senderId` and `direction` from the original row or existing sync and accepted-send receipts, without storing a second author record. Missing or conflicting evidence leaves those fields `null`. The recall event identifies the affected message; retrieve it for the current details.

For supported official message search indexes, recall also removes the original entry and its search terms. Unrelated entries stay in place. An unfamiliar index layout leaves local cleanup pending for inspection.

<Aside title="Good to know">
- **Some images use WeChat's WXGF format.** The original is kept, and a JPEG still is created with FFmpeg for viewing. Animation isn't preserved in the still.
- **Raw XML is never returned** as message content or as an attachment.
- **A recall doesn't erase everything.** Cached files, backups and anything the agent already saw are kept. It's not secure deletion.
- Link-card sends and thumbnails are new and not yet confirmed against how recipients' phones display them.
</Aside>
