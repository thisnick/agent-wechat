| You need | Why |
| --- | --- |
| **A computer to run the daemon**: Linux, macOS (Apple Silicon) or Windows | `wx serve` runs there and stays connected to WeChat. On Linux, glibc 2.36+ (Debian 12, Ubuntu 24.04 or newer). |
| **WeChat on your phone** | You log in by scanning a QR code or approving on the phone. |
| **FFmpeg and FFprobe** | Used for voice and video sends and some image previews. The Docker image includes them. |
| **Node 24.16+** | Only if you install with npm or pnpm. |
| **Optional: WeChat for Linux data** | To keep your existing chat history, agent-wechat can use the data folder of WeChat for Linux. Without it, you start with a new profile. |

Docker works too, on Linux or through Docker Desktop on macOS and Windows.

Next: [install](/setup/install/).

## What works

| Works | Not yet |
| --- | --- |
| Log in with a QR code or phone approval | Creating groups, inviting or removing members |
| Read history, contacts, groups and members | Fetching old history from WeChat's servers |
| Receive new messages as they arrive | Sending stickers and files above the initial 32 MiB limit |
| Send text, images, files, video, voice and link cards | Using data from WeChat for macOS or Windows |
| Download images, files, video and voice | Proxy support for outgoing connections |
| Recall your own messages | |
| Mark chats read and notify your other devices | |

<Aside title="Good to know">
- **History comes from your WeChat data, not the server.** WeChat doesn't resend old chats to a new login, so a new profile only fills up from now on.
- **Your data stays in WeChat's own format.** agent-wechat reads and writes the same files WeChat for Linux uses, so it can pick up where that app left off.
- OpenClaw and other clients can run on any machine that can reach the daemon.
- See the [capability checklist](https://github.com/thisnick/agent-wechat/blob/main/packages/native-client-rust/FEATURES.md) for what has been tested and how.
- [Attachment limits](/use/media/) differ by send kind; the larger ordinary-file path has a separate validation status.
</Aside>
