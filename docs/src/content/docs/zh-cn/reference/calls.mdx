使用 `wx calls status` 检查实时通话支持状态，随后可通过 CLI、OpenClaw 或底层的[控制 API](../calls-api/) 与[媒体 API](../calls-media/) 进行交互。
当前的底层后端支持单聊语音通话；视频通话与多人会议功能保持关闭。通话元数据中严格区分 `kind`（`direct` 单聊 / `conference` 群聊）与 `callType`（`voice` 语音 / `video` 视频）。

## 检查可用性

1. 在源码构建中执行 `wx calls --help`。父命令仅输出帮助信息，不发起网络连接、不执行登录，也不打开本地音频设备。
2. 针对目标守护进程执行 `wx calls status`。普通启动路径会加载原生通话后端。尚未通过认证的账号会汇报空的 `capabilities: {}`。
3. 必须在拥有对应 capability 后才可接入通话。单独存在 API 路由或配置了插件并不代表通话能力实际就绪。

常规源码构建与发布版构建均内置了通话与本地音频支持；[源码构建](../build/#included-features) 列出了对应先决条件。无界面 (Headless) 守护进程不会主动打开本地麦克风或扬声器。运行时账号权限与声明的能力决定了客户端是否可以参与通话。

## API 连接方式

参考 [通话控制 API 参考](../calls-api/) 获取路由列表、完整的命令/事件载荷、来电示例与所有权规则。独立的 [通话媒体 API 参考](../calls-media/) 详细说明了附加协议、JSON 控制流以及原始 PCM 分片规范。

控制 WebSocket 连接可以仅用于监控通话而不做应答。首个成功应答的客户端获得来电的独占所有权；外呼通话则天然归发起方所有。同一账号下的其他授权客户端能够接收到包括 `callType: "voice"` 在内的通话元数据，但无法接收音频流，且在忙碌期间无法发起其他新通话。所有通话接口均需要包含 `calls` 作用域的令牌及 Authorization 请求头。

控制连接必须在通话整个生命周期内保持在线。断线重连无法重新夺回已有所有权。服务端接收到挂断命令后将开始清理流程，请等待 `ended` 事件。若挂断结果呈现 `uncertain`（未决），在发起下一通呼叫前必须先行核查状态。

服务端会检测连接心跳与通话活跃度。呼出接听超时与来自已认证对端的新数据包超时均为 1 分钟。连接超时与媒体规则请参见 API 参考文档。

## CLI 命令行与 OpenClaw

| 命令 | 行为说明 |
| --- | --- |
| `wx calls devices` | 列出本地麦克风与扬声器设备 ID，不连接守护进程亦不启动音频流 |
| `wx calls monitor --json` | 仅监听通话事件，不打开本地音频设备 |
| `wx calls monitor` | 显示“等待来电。Ctrl-C 退出。”直到有电话呼入。确认接听后打开音频设备 |
| `wx calls dial 联系人` | 使用本机的麦克风和扬声器发起呼出 |
| `wx calls answer [CALL_ID]` | 使用本地音频应答当前匹配的来电邀请 |

发布版可执行二进制内置了本地音频支持。在守护进程确认振铃后，监听终端会弹出接听提示。接听始终绑定到选定的呼叫，即使后续有新来电也不会错乱。

建议先执行 `wx calls devices` 查询设备，然后通过 `--input-device INPUT_ID --output-device OUTPUT_ID` 指定设备：
`wx calls dial 联系人 --input-device INPUT_ID --output-device OUTPUT_ID`。
若省略参数，将取用操作系统默认设备。Linux 接受 PulseAudio 或 PipeWire-Pulse 设备名；Windows 接受端点 GUID；macOS 在系统设置中选择默认设备（当前适配器不支持自定义端点 ID）。

交互式通话会在音频电平表上方显示快捷键提示：

```text
m + 回车   静音/取消静音   h + 回车   挂断通话
Ctrl-C     结束通话        ? + 回车   查看快捷键
Mic [#######...] -18dB  Speaker [########..] -10dB
>
```

音量越大条状图越高，静音时回落。`0 dB` 表示数字满幅；`!` 标记近期接近削波失真的瞬时峰值。麦克风静音时无发送信号。扬声器电平测量的是实际送入播放管道的数据，而非物理旋钮或房间内的声音。JSON 模式、重定向输出或过窄的终端窗口会自动抑制电平表显示。

执行 `WX_CALL_DEBUG=1 wx calls monitor` 可以在操作通话快捷键时向 stderr 输出带时间戳的调试追踪信息。它会展示已剔除媒体所有者令牌的来电事件、首个音频帧是否成功写入 Socket，以及 CLI 收到的任何 WebSocket 关闭状态码与原因。

在 OpenClaw 中配置独立的语音/视频权限、实时语音对话模型与 OpenAI 凭据请参考 [配置语音通话](/zh-cn/openclaw/calling/)。

:::note[使用提示]
旧版微信中继节点可能会跨发送方复用音频 Nonce 随机数。为了兼容性，守护进程会继续保持通话，这在一定程度上削弱了音频的机密性与完整性。

Linux CLI 音频需要系统已安装 `libpulse0` 以及正常运行的 PulseAudio 或 PipeWire-Pulse 服务。无界面 Docker 镜像内置了客户端库，但仅运行守护进程无需音频硬件或音频服务。
:::
