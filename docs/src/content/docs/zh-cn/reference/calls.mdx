使用 `wx` 通过本机的麦克风、扬声器和摄像头，发起或加入单聊或群会议的语音与视频通话。OpenClaw 设置（仅语音）请参考[设置通话](/openclaw/calling/)。

## 检查可用性 \{#check-availability}

1. 选择守护进程和账号，然后运行 `wx calls status`。没有当前已认证会话的账号会报告 `capabilities: {}`。执行某项操作前，需要确认对应的能力已经可用（`directAudio`、`directVideo`、`conferenceAudio`、`conferenceVideo`）。
2. 运行 `wx calls devices`，列出本地的麦克风、扬声器和摄像头。
3. 按下文发起或应答通话。清理完成前请保持拥有通话的终端打开；其他客户端无法接管。

## 单聊通话与监听 \{#direct-calls-and-monitoring}

| 命令 | 行为 |
| --- | --- |
| `wx calls monitor --json` | 只观察事件，不打开音频或摄像头设备 |
| `wx calls monitor` | 等待邀请；接受时打开音频（视频通话时还会打开摄像头） |
| `wx calls dial CONTACT` | 使用本地麦克风和扬声器发起单聊语音通话 |
| `wx calls dial CONTACT --video` | 发起单聊视频通话，采集摄像头画面并在终端中预览 |
| `wx calls answer [CALL_ID]` | 应答当前匹配的语音或视频来电 |

使用 `--camera <source>` 选择摄像头（`auto`、`off`、用于 FFmpeg 动画测试图案的 `test`、用于循环播放媒体文件的 `file:<path>`，或设备路径或名称）。使用 `--camera-off` 可以加入视频通话但不发送摄像头画面。使用 `--muted` 可以静音启动。

守护进程确认振铃后，监听界面会显示单聊来电。对于会议邀请，输入 `j NUMBER`。离开后会回到监听状态；单独执行的发起或加入命令会直接退出。JSON 监听不会自动应答或加入。

## 群会议通话 \{#conference-calls}

1. 发起需要 `conferenceCreate` 和 `conferenceAudio`；加入需要 `conferenceJoin` 和 `conferenceAudio`。使用 `--video` 时还需要 `conferenceVideo`。
2. 在已有群中，带上联系人 ID 发起通话：

   ```sh
   wx calls conference start GROUP_ID --invite CONTACT_A --invite CONTACT_B
   wx calls conference start GROUP_ID --invite CONTACT_A --video
   ```

   或加入当前邀请：

   ```sh
   wx calls conference join GROUP_ID
   ```

   如果没有当前邀请，加入会失败；命令不会创建房间。
3. 连接后即可开始说话。接收到的音频会混音播放，接收到的视频会在终端中显示：

   ```text
   Connected. Audio tracks: 1, video tracks: 1.
   ```

## 音频、视频与通话中控制 \{#audio-video-and-in-call-controls}

先运行 `wx calls devices`，再用 `wx calls dial CONTACT --input-device INPUT_ID --output-device OUTPUT_ID` 选择设备。不指定这些选项时，使用操作系统的默认设备。Linux 接受 PulseAudio 或 PipeWire-Pulse 的名称；Windows 接受设备端点 ID。在 macOS 上，请在系统设置中选择默认设备；不支持自定义端点 ID。

交互式通话会显示控制项、电平表；视频通话时还会在终端中以 24 位 TrueColor 预览视频。按键后需要按 Enter。`l` 或 `h` 会离开通话，并在 `monitor` 中返回监听。按 Ctrl-C 会离开通话，并在短暂清理后退出命令。

```text
m + Enter    Microphone          v + Enter    Camera (video calls)
s + Enter    Speaker             i + Enter    Invite
p + Enter    Participants        d + Enter    Devices
l/h + Enter  Leave call          ? + Enter    Help
Ctrl-C       Leave and exit
Mic [#######...] -18dB  Speaker [########..] -10dB
Alice [######....] -24dB joined mic on cam on
Bob   [..........] -60dB joined mic off
>
```

电平表测量的是数字 PCM；`0 dB` 为满量程，`!` 表示近期出现接近削波的峰值。Mic 测量外发信号；Speaker 测量混音后的播放信号，而不是硬件音量。即使关闭播放，各参与人的电平也会在混音前测量各自的音源。静音或安静并不能证明对方已静音或已离开。无法归属到具体参与人的音源会显示音轨标签。电平表和终端视频不会出现在 JSON 或重定向输出中；按 `p` 可查看完整名单。

使用 `i` 搜索联系人，或输入 `invite CONTACT_ID OTHER_ID` 发出邀请。提交邀请并不代表对方已经加入。邀请只能在会议中使用；无法把单聊升级为会议。按 `d` 后，可用 `d input NUMBER`、`d output NUMBER` 或 `d default` 切换设备。准备设备时当前音频会继续运行，但切换时可能会短暂中断。输入 `cancel` 可关闭选择器。

鉴权、所有权、二进制 `WXCM` 音视频帧和编解码器协商，请参考[通话 API](../calls-api/)与[媒体参考](../calls-media/)。

:::note[使用提示]
当前版本将原生通话限制为 20 分钟；更长的通话仍需验证。直接升级为会议和屏幕共享暂不可用。离开只会结束你自己的参与，不会结束房间。通话以未确定状态结束时，请先核实，再发起下一次通话。

外发摄像头采集和守护进程端的视频转码需要 `ffmpeg` 位于 `PATH` 中（或设置 `WX_FFMPEG_BIN`），并支持 HEVC（`hevc`/`libx265`）、H.264（`h264`/`libx264`）或 MJPEG 编解码器。CLI 使用独立的 JPEG 帧显示接收到的视频；对方改变方向时，CLI 会在本地旋转画面。

旧版微信中继可能会在不同发送方之间复用音频 Nonce 随机数。为了兼容，守护进程会继续通话，但这会削弱音频的机密性和完整性。

源码构建和正式发布构建都包含音频支持；参见[构建前提](../build/#included-features)。Linux 本地音频需要 `libpulse0`，以及 PulseAudio 或 PipeWire-Pulse。守护进程、帮助信息和 JSON 监听不需要本地设备或声音服务。`wx calls --help` 不会连接或登录。

`WX_CALL_DEBUG=1 wx calls monitor` 会在 stderr 输出带时间戳的事件，但不包括媒体所有者令牌、首帧提交和 WebSocket 关闭的详细信息。
:::
