无需 Daemon 或官方可执行程序，即可直接使用这些库。连接到正在运行的 Daemon 的应用程序可以使用 [HTTP API](/use/api/)。

| Crate | 用途 |
| --- | --- |
| [wechat-protocol](https://docs.rs/wechat-protocol) | 认证、传输、同步与消息编解码 |
| [wechat-profile](https://docs.rs/wechat-profile) | Profile 密钥、联系人、历史记录、缓存媒体与经过校验的写入器 |
| [wechat-calls](https://docs.rs/wechat-calls) | 语音会话与媒体基础组件、PCM 混音及可选的 Opus |
| [wechat-media](https://docs.rs/wechat-media) | 图像检查与解码 |
| [wechat-platform](https://docs.rs/wechat-platform) | 私有文件与操作系统支持 |

## 添加依赖 \{#add-dependencies}

1. 为所有库选择相同的已发布 Rust 库版本。将下面的 `VERSION` 替换为该版本号。`wechat-calls` 与账号所有者客户端 API 首次随 conference 发布版本提供；更早的版本中不包含它们。

   ```bash
   cargo add wechat-protocol@=VERSION wechat-profile@=VERSION
   ```

2. 使用 Rust 1.93.1+、C 编译器、Make 与 Perl 进行构建。Cargo 会自动解析所依赖的支持库。原生 Opus 还需要 CMake 与 C++ 编译器。

自 2.3.2 之后的版本起，Rust 库的版本号与 CLI、Daemon 和 OpenClaw 插件保持一致，且每次发布都会同时发布全部五个库。此前的库版本（直至 2.2.0）单独编号；请选择 crates.io 上列出的版本。

## 读取已停止的 Profile \{#read-a-stopped-profile}

停止 Profile 的写入进程，或提供一致的副本，然后加载受保护的密钥文件。快照标志仅记录调用方的确认，并不会停止其他进程。

```rust
use wechat_profile::{KeyFile, ListQuery, ProfileLocation, ProfileReader, ReadOptions};

fn contacts(profile: &str, keys_path: &str) -> wechat_profile::Result<()> {
    let reader = ProfileReader::open(
        ProfileLocation::new(profile)?, KeyFile::load(keys_path)?, ReadOptions {
            stopped_or_consistent_snapshot: true,
            ..Default::default()
        },
    )?;
    println!("{} contacts", reader.contacts(&ListQuery::default())?.items.len());
    Ok(())
}
```

读取缓存媒体时绝不会发起下载。拥有该 Profile 的应用程序可以使用 `OwnedReaderCache`，并由其自行同步。

`contacts` 列出当前的记录行。若需获取某个确切存储身份（包括保留下来的已删除联系人或群聊记录），请使用 `reader.contact(username)`。在修改联系人或群聊之前，请检查返回的标志位；仅有存储记录并不意味着该对象符合修改条件。

## 发送单条文本消息 \{#send-one-text-message}

操作均为 `NativeClient` 上的方法。应用程序负责凭据存储、恢复与 Profile 回写。

1. 调用 `start_qr_login`，轮询直至 `LoginStatus::Approved`，然后调用 `complete_login`。将返回的 `AccountState` 传入 `NativeClient::from_account(state, options)`。克隆出的句柄共享同一个账号所有者。操作不再接受单独的可变账号状态。
2. 提交前，先记录操作、唯一任务 ID 与 Unix 秒级时间戳。收件人请使用其确切的微信用户名（username）：

   ```rust
   use wechat_protocol::{wire, NativeClient, TextSendOptions, TextSendResult};

   async fn send_once(
       client: &NativeClient, recipient: &str, text: &str,
       task_id: &str, created_at: u32,
   ) -> anyhow::Result<TextSendResult> {
       let client_id = wire::client_message_id(task_id.as_bytes());
       anyhow::ensure!(client_id != 0, "Choose another task ID");
       client.send_text(recipient, text, TextSendOptions {
           created_at, client_message_id: client_id, source: None,
       }).await
   }
   ```

3. 检查 `accepted`、`returned_destination_matches` 与 `returned_client_id_matches`。回执中的 `server_message_id` 并不能证明接收方已播放该消息，也不能证明历史记录已回写。

在代码仓库中运行可执行示例，会显示新的登录二维码并提交一次消息：

```bash
cargo run --manifest-path packages/native-client-rust/Cargo.toml -p wechat-protocol --example send_text -- RECIPIENT UNIQUE_TASK_ID "Hello from Rust"
```

服务端接收后会输出 `"accepted": true`。`--help` 不会发起任何网络请求。`qr_login`、`sync_once` 与 `protobuf` 分别演示登录、单页同步以及本地编解码。`sync_once` 不保存游标；持续接收消息的程序必须先保留同步命令，然后再推进游标。

## 表情 \{#stickers}

`wechat-media::prepare_sticker` 会为调用方拥有的源文件进行准备（可选择适配或裁剪），并返回 GIF、静态图和抽样帧输出。`sticker_export_gif` 会保留已有的 GIF 字节；`export_sticker_pack` 会在调用方的文件系统中写入一个所选表情包以及可续传的校验和索引。

`NativeClient` 提供“我的表情”的分页与元数据、有上限的上传分块、“我的表情”的修改操作、表情包的分页、详情与说明，以及原始的成员关系确认。`StickerId::parse` 会规范化内容标识；`StickerPackId::parse` 则将产品标识分开保存。使用这些传输方法的应用需自行负责提交日志和 Profile 回写。读取缓存的 Profile 数据绝不会获取缺失的媒体。

在本工作区内，`wechat-core` 提供 `core.stickers(account)?`，这是一个绑定账号的异步句柄，支持 `list`、`get`、`media`、`prepare`、`add_prepared`、`save_received`、`move_after`、`remove`、`packs`、`browse`、`pack`、`items`、`add_pack`、`remove_pack`、`acquire`、`acquire_pack`、`acquire_preview`、`send`、`sync` 和 `job`。它负责账号门控并使用已有任务；文件系统导出不属于该句柄。`wechat-core` 是 Daemon 的实现，并非单独发布的 HTTP 客户端 crate。外部应用可以使用[表情 REST 资源](/reference/stickers/)。

## 发送图片与视频 \{#send-images-and-videos}

在调用协议发送方法之前，请先准备并上传各个副本。每个方法都会处理两种画质：

| 方法 | `upload.original: None` | `upload.original: Some(...)` |
| --- | --- | --- |
| `NativeClient::send_image` | 高清与缩略图 | 另包含原图 |
| `NativeClient::send_video` | 播放版与缩略图 | 另包含原始视频 |

`UploadedImage.original` 现为 `Option<UploadedMedia>`。迁移 Rust 调用方时，请将已有的原图包装为 `Some(...)`，并在读取该字段时处理 `None` 的情况。使用 Daemon [媒体 API](/use/quality/) 的应用程序则改为在发送请求中选择画质。

## 使用通话媒体 \{#use-calling-media}

请使用相同的 Rust 库版本添加 `wechat-calls`。它不会打开任何设备，也不会创建 Tokio 运行时。示例请参考其 [Crate 指南](https://docs.rs/crate/wechat-calls/latest)。

| Features | 用途 |
| --- | --- |
| 默认 `native-runtime` | 原生会话与媒体集成，以及协议和 Opus 支持 |
| 禁用默认特性 + `native-opus` | 不依赖账号的编解码与 PCM 工具 |
| 禁用默认特性 | 可移植的 PCM、队列、节拍控制与混音，包括 WebAssembly |

高级 `client.calls()` 门面接口尚未完成。目前完整的通话操作请使用[通话 API](../calls-api/)。[Crate 架构](../../how-it-works/rust-crates/)说明了各库之间的依赖关系。

## Profile 写入 \{#profile-writes}

`stage_*` 准备字节数据，`apply_*` 应用逻辑更新，`publish_*` 将字节安装到 Profile 中的路径。这些是 API 名称，并非官方客户端的名称；`apply_*` 与 `publish_*` 的职责有部分重叠，且不保证整个操作是原子的。MMKV 暂存会生成加密数据以及匹配的 `.crc` 元数据。发布时会使用临时文件。`WriteOptions::durable_intent_id` 指向你事先保存的恢复记录；该库无法验证此记录是否存在。

<Aside title="使用提示">
账号所有的异步方法使用传输 Worker。在异步应用中，阻塞式引导方法需要阻塞 Worker。新的测试登录可能会使已有的桌面端会话下线；示例仅在内存中保存凭据。保存凭据时请加密，并在重试前先核查状态不确定的发送。Profile 写入器需要独占所有权、匹配的密钥以及受支持的架构。Linux 上的 Profile 支持并不代表兼容 Windows 或 macOS。部分媒体功能需要 FFmpeg。请固定依赖版本，并在升级前检查 API 变更。
</Aside>
