通话的命令与事件通过控制 WebSocket 收发。拥有所有权的控制连接可以附加独立的[二进制 `WXCM` v3 媒体 Socket](../calls-media/)。
[Rust crate 架构](../../how-it-works/rust-crates/)说明了各个包的职责。

## 路由与快照 \{#routes-and-snapshot}

所有路由都需要在 `Authorization` 请求头中携带账号授权的 `calls` Bearer 令牌。WebSocket 路由还接受由 `POST /v1/accounts/{account}/calls/tickets` 生成的一次性 `?ticket=` 查询参数（有效期 20 秒，并绑定到确切的账号、路由和通话 ID），供无法设置自定义升级请求头的客户端使用。标识符需要进行 URL 编码；切勿把 Bearer 令牌放入 URL。

| 方法 | 路径 | 响应 |
| --- | --- | --- |
| GET | `/v1/accounts/{account}/calls/current` | JSON 快照 |
| POST | `/v1/accounts/{account}/calls/tickets` | 一次性 WebSocket 票据（`socket`：`control` 或 `media`；`media` 需附带 `callId`） |
| WebSocket | `/v1/accounts/{account}/calls/socket` | JSON 控制消息（协议版本 3） |
| WebSocket | `/v1/accounts/{account}/calls/{callId}/media` | JSON 音轨生命周期消息，以及二进制 `WXCM` v3 音视频帧 |

```bash
curl -sS -H "Authorization: Bearer $TOKEN" \
  "$BASE/v1/accounts/$ACCOUNT/calls/current"
```

```json
{
  "conferenceInvitations": [{
    "invitationId": "invitation-example",
    "revision": 1,
    "groupId": "group@chatroom",
    "callerId": "contact-a"
  }],
  "capabilities": {
    "directAudio": true,
    "directVideo": true,
    "conferenceCreate": true,
    "conferenceJoin": true,
    "conferenceInvite": true,
    "conferenceAudio": true,
    "conferenceVideo": true
  },
  "availability": {
    "busy": false,
    "ownedByThisClient": false
  },
  "currentOffer": null,
  "currentPendingOffer": null,
  "currentCall": null,
  "audioFormat": {
    "sampleRate": 16000,
    "channels": 1,
    "frameMs": 20
  },
  "videoCapabilities": {
    "sendCodecs": ["h265", "h264", "jpeg"],
    "receiveCodecs": ["h265", "h264", "jpeg"],
    "maxWidth": 640,
    "maxHeight": 480,
    "maxFps": 15
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `capabilities` | 只列出可用的功能标志；缺少的标志表示不可用；`{}` 表示不能通话 |
| `conferenceInvitations` | 最新的不透明邀请 ID 与修订号，以及群聊和邀请人；不含房间凭据 |
| `currentPendingOffer` | 等待就绪或准备中的来电候选；不能应答 |
| `currentOffer` | 可以处理的来电；被认领或结束后清空 |
| `currentCall` | 当前通话的元数据，包括类型、种类、状态、会议参与人名单，或已上报的单聊控制状态 |
| `audioFormat` | 客户端与守护进程之间的 PCM 格式，与微信使用的编码无关 |
| `videoCapabilities` | 视频通话可用时，支持的视频发送与接收编码及上限 |

上报的会议参与人包含 `participantId`、`contactId` 和 `membership`（`joined` 已加入、`invited` 已邀请、`left` 已离开或 `unknown` 未知）。服务端提供麦克风状态时，`microphoneEnabled` 为 `true` 或 `false`；省略则表示未知。静音麦克风不会把参与人移出房间。

当存在 `status` 字段时，快照和 `participant.updated` 事件中会包含 `{code, kind}`。它描述信令进度，与成员状态相互独立：

| `code` | `kind` | 成员状态含义 |
| --- | --- | --- |
| 0 | `undefined` | 未知 |
| 1 | `joined` | 已加入 |
| 2 | `invited` | 已邀请，未加入 |
| 3 | `acknowledged` | 已邀请，未加入 |
| 4 | `left` | 已离开 |
| 5 | `cancelled` | 取消的结果 |
| 6 | `busy` | 忙线的结果 |
| 7 | `rejected` | 拒绝的结果 |
| 8 | `no_response` | 无应答的结果 |
| 其他 | `unknown` | 保留 `code`；不推断加入或离开 |

取消、忙线、拒绝和无应答本身并不能说明此前的参与人已经离开。麦克风状态同样与之独立。例如，已确认的邀请对应 `membership: "invited"` 和 `status: {"code": 3, "kind": "acknowledged"}`。

同一账号的观察者可以看到通话元数据，但看不到所有者令牌，也不能访问音频。HTTP 结果中的 `ownedByThisClient` 始终为 `false`：所有权属于控制 WebSocket。`busy` 只针对当前账号，包括任何阻止新通话的未决通话结果。每个账号都有自己的通话控制器。

## 会议命令 \{#conference-commands}

1. 检查所需操作对应的 `conferenceCreate`、`conferenceJoin`、`conferenceInvite` 和 `conferenceAudio` 能力。创建或加入之前，先通告外呼[就绪状态](#readiness)。
2. 要创建通话，请提供群 ID 以及 1 到 100 个联系人 ID：

   ```json
   {
     "type": "call.dial",
     "requestId": "create-1",
     "target": {
       "kind": "conference",
       "groupId": "group@chatroom",
       "invitees": ["contact-a", "contact-b"]
     },
     "callType": "voice"
   }
   ```

   要加入已有的通话，请从 `conferenceInvitations` 中选择一项，并发送其确切的 ID 与修订号：

   ```json
   {
     "type": "call.join",
     "requestId": "join-1",
     "invitationId": "invitation-example",
     "invitationRevision": 1
   }
   ```

   已过期、已撤回或已使用的邀请会被拒绝，返回 `offer_expired`。加入操作不会创建新房间。会议邀请使用 `call.join`，而不是单聊使用的 `call.answer`。
3. 发起或加入后保持所有权控制 Socket 打开。创建与加入会返回 `command.result`，其中包含通话 ID 和所有者令牌；随后等待 `call.state` 变为 `connected`。接通后如需邀请更多联系人，请发送：

   ```json
   {
     "type": "call.invite",
     "requestId": "invite-1",
     "callId": "example-conference",
     "contactIds": ["contact-c", "contact-d"]
   }
   ```

`call.invitation_result` 会分别报告首次邀请和之后每次邀请的结果；提交成功并不代表联系人已经加入。`participant.updated` 报告成员状态与麦克风的变化。`call.mute` 改变我们的麦克风；`call.hangup` 只让我们离开会议，其他参与人的通话会继续。
对于同一个我们拥有的通话，即使名单变化，离开操作仍然有效。通话正在结束时重复发送，不会再次提交离开操作。已确认的先前移除会在本地完成；结果未确认的，则保持不确定状态。
提交命令前请先检查上报的能力。当前版本不支持把单聊直接升级为会议。

## 协议版本 \{#protocol-version}

打开控制 Socket 后五秒内，声明支持的协议版本：

```json
{"type": "call.hello", "supportedProtocolVersions": [3]}
```

等待服务端的 `hello`，并在发送命令前检查 `protocolVersion`。守护进程只支持版本 3。省略声明时视为版本 1，且不会回退到旧版本。版本不匹配时，服务端会先返回以下消息，然后以 WebSocket 代码 1002 关闭连接：

```json
{"type":"protocol.error","code":"unsupported_protocol_version","clientVersions":[2],"serverVersions":[3]}
```

版本列表为空、为 null、有重复项或格式错误时，返回 `invalid_protocol_version`。CLI、共享 SDK 和 OpenClaw 插件都声明版本 3，并拒绝不支持的服务端。媒体连接单独协商版本。

## 客户端消息 \{#client-messages}

在**控制** Socket 上发送以下 JSON 文本消息。版本声明之后，每个命令都需要 `requestId`；只有完全相同的命令才能重用它。应答、拒绝、取消和挂断时，请使用最近收到的修订号。下面的修订号仅为示例。

### 就绪状态 \{#readiness}

先准备好音频通路，再通告就绪状态。仅建立连接时保持被动。

```json
{
  "type": "call.ready",
  "requestId": "ready-outgoing",
  "ready": true,
  "format": {
    "sampleRate": 16000,
    "channels": 1,
    "frameMs": 20
  },
  "scope": {
    "kind": "outgoing"
  }
}
```

为某个待处理的来电就绪：

```json
{
  "type": "call.ready",
  "requestId": "ready-offer",
  "ready": true,
  "format": {
    "sampleRate": 16000,
    "channels": 1,
    "frameMs": 20
  },
  "scope": {
    "kind": "offer",
    "callId": "example-call",
    "expectedRevision": 1
  }
}
```

同时为呼入和呼出通话就绪，或撤销就绪：

```json
{
  "type": "call.ready",
  "requestId": "ready-all",
  "ready": true,
  "format": {
    "sampleRate": 16000,
    "channels": 1,
    "frameMs": 20
  },
  "scope": {
    "kind": "all"
  }
}
```

```json
{
  "type": "call.ready",
  "requestId": "not-ready",
  "ready": false,
  "format": {
    "sampleRate": 16000,
    "channels": 1,
    "frameMs": 20
  }
}
```

省略 `scope` 等同于 `all`。

### 发起或应答 \{#start-or-answer}

```json
{
  "type": "call.dial",
  "requestId": "dial-1",
  "target": {
    "kind": "direct",
    "contactId": "example-contact"
  },
  "callType": "voice"
}
```

```json
{
  "type": "call.answer",
  "requestId": "answer-1",
  "callId": "example-call",
  "expectedRevision": 3
}
```

发起呼叫的 Socket 拥有该外呼通话。对于呼入通话，第一个成功应答的客户端获胜；其他客户端会收到 `already_claimed`。

### 拒绝、取消或挂断 \{#reject-cancel-or-hang-up}

拒绝来电、在对方接听前取消外呼，或在接听或接通后挂断：

```json
{
  "type": "call.reject",
  "requestId": "reject-1",
  "callId": "example-call",
  "expectedRevision": 3
}
```

```json
{
  "type": "call.cancel",
  "requestId": "cancel-1",
  "callId": "example-call",
  "expectedRevision": 4
}
```

```json
{
  "type": "call.hangup",
  "requestId": "hangup-1",
  "callId": "example-call",
  "expectedRevision": 5
}
```

### 音频与视频控制 \{#audio-and-video-controls}

`call.mute` 可以静音外发音频，`call.camera` 可以切换视频通话中的本地摄像头，`call.clear_audio` 可以清空排队中的外发音频；参见[流代际](../calls-media/#mute-camera-toggle-and-interrupt)。`call.mute` 只在守护进程中屏蔽本客户端的外发流，并会在单聊语音、单聊视频和群会议通话中请求更新我们在房间中的麦克风状态。`call.camera` 请求更新我们的摄像头状态，并推进视频发送音轨的代际。两者都不能控制其他参与人的设备。

```json
{
  "type": "call.mute",
  "requestId": "mute-1",
  "callId": "example-call",
  "muted": true
}
```

```json
{
  "type": "call.camera",
  "requestId": "camera-1",
  "callId": "example-call",
  "enabled": false
}
```

```json
{
  "type": "call.clear_audio",
  "requestId": "clear-1",
  "callId": "example-call"
}
```

参与视频通话时，可在 `call.ready` 中加入可选的 `video` 能力（`sendCodecs`、`receiveCodecs`、`maxWidth`、`maxHeight`、`maxFps`）。在 `call.dial`、`call.answer` 和 `call.join` 中，还可以使用可选的 `cameraEnabled` 与 `muted` 标志。

### 会议邀请与结果 \{#conference-invitations-and-results}

`conference.invitations` 会替换当前的邀请列表。空数组会清空列表；邀请 ID 只在所属账号内有效，并且不含房间凭据。

```json
{
  "type": "conference.invitations",
  "invitations": [{
    "invitationId": "invitation-example",
    "revision": 1,
    "groupId": "group@chatroom",
    "callerId": "contact-a"
  }]
}
```

所有者会收到每个联系人的结果，并通过 `requestId` 与创建或邀请命令关联。例如，之后的 `invite-1` 命令可能产生如下结果：

```json
{
  "type": "call.invitation_result",
  "callId": "example-conference",
  "requestId": "invite-1",
  "results": [
    {
      "contactId": "contact-c",
      "status": "submitted",
      "serviceCode": 0,
      "verificationRequired": false
    },
    {
      "contactId": "contact-d",
      "status": "unknown",
      "verificationRequired": false
    }
  ]
}
```

| 状态 | 含义 |
| --- | --- |
| `submitted` | 服务端已接受邀请提交 |
| `rejected` | 提交被拒绝 |
| `unknown` | 服务端没有提供该联系人的结果 |
| `uncertain` | 操作可能已到达服务端；请勿自动重试 |

无法获取时省略 `serviceCode`。`verificationRequired: true` 表示服务端要求验证；该事件不包含验证链接，也不会完成验证步骤。邀请结果与房间成员状态互不影响。

### 命令结果 \{#command-results}

根据 `requestId` 对应到你发出的命令。就绪成功时不会认领通话：

```json
{
  "type": "command.result",
  "requestId": "ready-outgoing",
  "status": "accepted",
  "callId": null,
  "ownerToken": null,
  "code": null
}
```

成功认领通话时，会返回用于附加媒体的保密令牌：

```json
{
  "type": "command.result",
  "requestId": "dial-1",
  "status": "accepted",
  "callId": "example-call",
  "ownerToken": "<secret owner token>",
  "code": null
}
```

创建和加入会议时，所有权的认领方式相同。加入成功的 `join-1` 响应如下：

```json
{
  "type": "command.result",
  "requestId": "join-1",
  "status": "accepted",
  "callId": "example-conference",
  "ownerToken": "<secret owner token>",
  "code": null
}
```

`accepted` 表示操作已开始，并不代表已经接通。完全相同的请求可能返回 `replayed`。被拒绝的命令返回 `error` 和固定的错误代码：

```json
{
  "type": "command.result",
  "requestId": "ready-outgoing",
  "status": "replayed",
  "callId": null,
  "ownerToken": null,
  "code": null
}
```

```json
{
  "type": "command.result",
  "requestId": "answer-1",
  "status": "error",
  "callId": null,
  "ownerToken": null,
  "code": "already_claimed"
}
```

### 待处理与可处理的来电 \{#pending-and-actionable-offers}

待处理的候选来电，其阶段为 `waiting_for_ready` 或 `preparing`：

```json
{
  "type": "call.pending",
  "offer": {
    "callId": "example-call",
    "revision": 1,
    "kind": "direct",
    "callType": "voice",
    "callerId": "example-contact",
    "phase": "waiting_for_ready"
  }
}
```

```json
{
  "type": "call.pending",
  "offer": null
}
```

可处理的来电，应使用其修订号进行应答或拒绝：

```json
{
  "type": "call.offered",
  "offer": {
    "callId": "example-call",
    "revision": 3,
    "kind": "direct",
    "callType": "voice",
    "callerId": "example-contact"
  }
}
```

### 状态与可用性 \{#state-and-availability}

会议状态包含群聊和最新的参与人名单。在下面的例子中，`contact-a` 没有上报麦克风状态；`contact-b` 仍在会议中，麦克风已关闭：

```json
{
  "type": "call.state",
  "call": {
    "callId": "example-conference",
    "revision": 5,
    "kind": "conference",
    "callType": "voice",
    "direction": "outgoing",
    "state": "connected",
    "ownedByThisClient": true,
    "groupId": "group@chatroom",
    "participants": [
      {"participantId": "member-4", "contactId": "contact-a", "membership": "joined"},
      {"participantId": "member-5", "contactId": "contact-b", "membership": "joined", "microphoneEnabled": false}
    ]
  }
}
```

名单变化会推进通话修订号，并向同一账号的客户端发送 `participant.updated`，随后发送更新后的通话快照：

```json
{
  "type": "participant.updated",
  "callId": "example-conference",
  "revision": 6,
  "participant": {
    "participantId": "member-5",
    "contactId": "contact-b",
    "membership": "left",
    "status": {"code": 4, "kind": "left"}
  }
}
```

关联音轨时请使用上报的 `participantId`，不要假定它等于联系人 ID。被移除的参与人可能先以 `membership: "left"` 出现，然后从快照的当前名单中消失。

单聊通话继续使用如下结构：

```json
{
  "type": "call.state",
  "call": {
    "callId": "example-call",
    "revision": 5,
    "kind": "direct",
    "callType": "voice",
    "direction": "incoming",
    "state": "connected",
    "ownedByThisClient": true,
    "controls": [
      {
        "participantId": "example-contact",
        "control": {
          "kind": "microphone",
          "muted": false
        }
      }
    ]
  }
}
```

```json
{
  "type": "call.state",
  "call": {
    "callId": "example-call",
    "revision": 6,
    "kind": "direct",
    "callType": "voice",
    "direction": "incoming",
    "state": "ending",
    "ownedByThisClient": true
  }
}
```

```json
{
  "type": "call.state",
  "call": {
    "callId": "example-call",
    "revision": 7,
    "kind": "direct",
    "callType": "voice",
    "direction": "incoming",
    "state": "ended",
    "ownedByThisClient": true
  }
}
```

```json
{
  "type": "calls.availability",
  "availability": {
    "busy": false,
    "ownedByThisClient": false
  }
}
```

通话状态包括 `offered`、`dialing`、`ringing`、`connecting`、`connected`、`ending`、`ended` 和 `uncertain`。进入 `ending` 时应停止音频；守护进程完成清理期间，保持控制连接。`uncertain` 表示后端结果未经确认。即使本地会话已关闭，其网络收据仍会保留。

### 参与人控制事件 \{#participant-control-events}

对于单聊通话，`call.control` 报告参与人的控制状态。支持的控制类型是 `microphone`（`muted: true|false`）和 `camera`（`enabled: true|false`）。`participantId` 是单聊目标或来电所使用的联系人 ID。

```json
{
  "type": "call.control",
  "callId": "example-call",
  "participantId": "example-contact",
  "control": {
    "kind": "microphone",
    "muted": true
  }
}
```

```json
{
  "type": "call.control",
  "callId": "example-call",
  "participantId": "example-contact",
  "control": {
    "kind": "camera",
    "enabled": true
  }
}
```

这些事件发送给所有者和同一账号的观察者，无需回复，客户端也可以忽略。状态未变化时不会重复发送。最新已知的值也会出现在 HTTP 快照、`hello` 和 `call.state` 的 `currentCall.controls` 中；省略 `controls` 表示尚未上报状态。会议的麦克风和摄像头变化会出现在 `participants`（`microphoneEnabled`、`cameraEnabled`）和 `participant.updated` 中；省略的值表示未知，而不是 `false`。

### 单聊通话对端信令状态 \{#direct-call-peer-signaling-status}

对于单聊通话，`call.peer_status` 会报告对端在房间信令中的状态变化（对端设备振铃后为 `acknowledged`，接听后为 `joined`，另有 `rejected`、`busy`、`no_response` 或 `left`）。它使用与群会议参与人相同的 `{code, kind}` 表：

```json
{
  "type": "call.peer_status",
  "callId": "example-call",
  "participantId": "example-contact",
  "status": {
    "code": 3,
    "kind": "acknowledged"
  }
}
```

状态码未变化时不会重复发送事件。启用会发出 `call.peer_status` 的构建时，请同时升级通话客户端和守护进程；较旧的协议 3 客户端遇到无法识别的事件类型时会关闭 Socket。升级后的客户端会在握手完成后忽略控制 Socket 和媒体 Socket 上未知的未来服务端事件 `type`，这样新增的服务端消息就不会断开正在进行的通话。

### 轨道代际与错误 \{#track-generations-and-errors}

`call.clear_audio`、`call.mute` 或 `call.camera` 成功后，受影响的发送音轨会推进代际：

```json
{
  "type": "track.updated",
  "callId": "example-call",
  "track": {
    "media": "audio",
    "id": 1,
    "generation": 2,
    "direction": "send",
    "format": {
      "sampleRate": 16000,
      "channels": 1,
      "frameMs": 20
    }
  }
}
```

接收音轨的 `track.added` 和 `track.removed` 示例，以及它们与二进制 `WXCM` 帧的先后顺序，请参见[媒体参考](../calls-media/#receive-tracks-and-video-keyframes)。

控制 Socket 出现连接级故障时，会发送 `call.error`：

```json
{
  "type": "call.error",
  "code": "forbidden"
}
```

错误代码包括 `invalid_request`、`busy`、`already_claimed`、`offer_expired`、`not_owner`、`unsupported`、`media_not_ready`、`outcome_unknown`、`capacity`、`stale`、`forbidden` 和 `closed`。丢失的回复不能作为自动重试的依据。

:::note[使用提示]
重新连接不会恢复所有权。控制消息上限为 16 KiB。服务端每 15 秒发送一次 WebSocket Ping；如果连接 60 秒内没有任何入站流量，服务端会关闭它。所有者的控制 Socket 关闭后，媒体会停止并开始清理通话；其他观察者无法保持所有权。静音或音频安静，都不算控制连接丢失。

守护进程重启后，之前的通话会在本地结束，`currentCall` 为空。旧请求不会被重放。正常关闭时，守护进程会先尝试清理通话；未确认的网络结果会与本地通话状态分开记录。`kind` 为 `direct` 或 `conference`；`callType` 为 `voice` 或 `video`，前提是相应能力可用。屏幕共享和单聊升级为会议暂不可用。原生通话目前有 20 分钟的安全时长限制。
:::
