在 `channels.agent-wechat.calls` 下配置实时通话支持。语音和视频默认均处于禁用状态。当前的守护进程和插件支持直接单聊语音通话。

## 连接守护进程

1. 完成[快速接入](../setup/)并执行 `wx calls status`。守护进程必须声明 `directAudio: true`；构建选项请参见[实时通话](/zh-cn/reference/calls/)。
2. 为通道令牌补充 `calls` 权限作用域（与既有的消息读写权限并列）：

   ```bash
   wx tokens create openclaw-calling --accounts ACCOUNT_ID \
     --scopes read --scopes media --scopes send --scopes login \
     --scopes read-state --scopes calls
   ```

   在通道既有的 `native.token` SecretRef 中使用生成的新令牌。未包含 `calls` 权限的令牌无法调用通话接口。

## 配置实时语音与访问控制

将以下示例合并到你的 OpenClaw 通道及智能体配置中。替换示例中的联系人 ID 与管理员所有者 ID。
在 **Gateway 进程的环境变量** 中设置 `OPENAI_API_KEY`。

```json
{
  "secrets": {
    "providers": {
      "voiceenv": {
        "source": "env",
        "allowlist": ["OPENAI_API_KEY"]
      }
    }
  },
  "agents": {
    "entries": {
      "main": {
        "tools": {
          "alsoAllow": ["wechat_call"]
        }
      }
    }
  },
  "channels": {
    "agent-wechat": {
      "calls": {
        "voice": {
          "enabled": true,
          "agentId": "main",
          "inboundPolicy": "allowlist",
          "inboundAllowFrom": ["allowed-contact-id"],
          "outboundPolicy": "allowlist",
          "outboundAllowTo": ["allowed-contact-id"],
          "outboundToolAllowFrom": ["owner-id"],
          "maxDurationSeconds": 3600,
          "realtime": {
            "provider": "openai",
            "voice": "marin",
            "instructions": "Keep spoken replies concise.",
            "agentContext": { "enabled": true },
            "providers": {
              "openai": {
                "apiKey": {
                  "source": "env",
                  "provider": "voiceenv",
                  "id": "OPENAI_API_KEY"
                }
              }
            }
          },
          "toolPolicy": "none"
        },
        "video": {
          "enabled": false
        }
      }
    }
  }
}
```

`apiKey` 还支持通过 OpenClaw 文件/可执行命令/密钥存储形式的 SecretRef，或直接传入字符串密钥。若省略，OpenClaw 将取用选定智能体的 OpenAI 认证或 Gateway 环境变量。仅拥有普通文本智能体订阅并不一定具备实时语音 API (Realtime) 的访问权限。守护进程 Token 与 OpenAI Key 属于完全隔离的两种凭据。

`wechat_call` 工具是可选的：上述示例将其授权给 `main` 智能体用于查看状态、发起外呼或挂断通话。将其授权给任何需要为你拨打电话的智能体（例如负责群聊回复的智能体）；通话本身始终以 `calls.voice.agentId` 身份运行。自动接听呼入电话并不强制要求智能体具备该工具。

保存配置文件后重启 OpenClaw Gateway。当守护进程空闲时，已就绪的语音服务会汇报为 `available`；若提供商异常或能力不匹配则会汇报为 `unavailable`，此时呼入电话将保持不予接听状态。

## 模型配置与运行行为

以下所有配置路径均相对于 `calls.voice`。

| 配置项 | 行为 / 默认值 |
| --- | --- |
| `realtime.provider` | 必填项；目前支持的适配器为 `openai`。 |
| `realtime.model`, `realtime.voice` | 可选语音模型/声音角色；若未指定则使用提供商默认值。 |
| `realtime.instructions` | 可选的对话系统提示词引导，最长 4,000 字符。 |
| `realtime.agentContext.enabled` | 默认为 `false`。设为 `true` 可自动注入所选智能体 `IDENTITY.md` 与 `SOUL.md` 的片段。 |
| `agentId` | 必填项。用于确定声音角色、提供商鉴权以及被允许协同咨询的对应智能体。 |
| `toolPolicy` | 可设为 `none`、`safe-read-only` 或 `owner`。开启会话持久化时默认为 `safe-read-only`。 |
| `allowConsultSessionPersistence` | 设为 `true` 允许在通话期间使用 OpenClaw 会话进行协同咨询。 |
| `sessionScope` | `per-contact`（每个联系人保持一个会话，使智能体能够记住过往通话）或 `per-call`。参见[记忆过往通话](../call-memory/)。 |
| `consultation.summary`, `consultation.recentMessages`, `realtime.recentContext` | 为每次已接听的通话生成摘要，并与智能体共享最近的聊天记录（默认开启）；为下一次通话提供简要回顾（默认关闭）。参见[记忆过往通话](../call-memory/)。 |
| `realtime.consultPolicy` | `auto` 由模型自主决定何时咨询；`substantive` 要求其就事实与上下文发起咨询；`always` 在模型漏查时由呼叫方轮次强制触发咨询。 |
| `realtime.consultThinkingLevel`, `realtime.consultFastMode` | 可选的 OpenClaw 推理级别与咨询极速模式覆盖。 |
| `consultation.inboundSessionKey` | 可选的选定智能体已有会话，在首次接听来电时用来初始化新的通话会话。 |
| `consultation.timeoutMs` | 默认 30,000 毫秒；有效区间 1,000–120,000 毫秒。 |
| `maxDurationSeconds` | 默认 3,600 秒（1 小时）；有效区间 30–3,600 秒。达到该上限时插件将自动挂断。Native 守护进程当前最多支持持续通话 20 分钟。 |

语音实时模型负责自然语音对话；选定的 OpenClaw 智能体负责处理委托的复杂提问与允许的工具调用。呼入/呼出策略默认处于 `disabled`；白名单必须使用确切的联系人 ID，不支持 `*` 通配符。工具调用者还必须被列入 `outboundToolAllowFrom` 授权列表。普通文字消息收发权限不代表通话权限。

将 `realtime.model` 设置为以下 OpenAI 模型之一。若省略则使用提供商默认值 `gpt-realtime-2.1`。

| 模型 | 对话机制 | 智能体协同咨询 | 登录认证 |
| --- | --- | --- | --- |
| `gpt-realtime-2.1`, `gpt-realtime-2.1-mini`, `gpt-realtime-2` | 轮流发言；当呼叫方打断时立即停止。 | 通过工具调用。 | OpenAI API 密钥。 |
| `gpt-live-1-codex` (声音角色 `cove`) | 边听边说并自主处理打断。自我介绍为 ChatGPT：此路由不使用智能体的名称或人设角色。 | 委托给智能体。不支持 `consultPolicy: "always"`。 | OpenClaw 中智能体的 ChatGPT 登录（2026.10.10 或更新版本），其次为 API 密钥。 |
| `gpt-live-1` (声音角色 `marin`) | 边听边说并自主处理打断。使用智能体的名称与人设角色。 | 同 `gpt-live-1-codex`。 | OpenAI API 密钥。 |

语音模型会继承选定智能体已配置的身份。当开启工作区上下文 (`agentContext`) 时，实时提供商还会接收两个角色文件有边界的摘录内容。请确保这些文件内容适宜语音交互。

使用 `wechat_call` 发起的呼叫在启用协同咨询且该会话归属于 `calls.voice.agentId` 时，会使用发起请求的会话作为上下文。配置 `consultation.inboundSessionKey` 可在呼入时实现相同效果。OpenClaw 会在通话会话首次创建时，将该会话的上下文复制到通话会话中。请确保所选会话的历史记录适合呼入者。

当设置 `toolPolicy: "owner"` 时，如果通话参与者的微信 ID 与 `commands.ownerAllowFrom` 中的 `agent-wechat:<WeChat ID>` 条目完全一致，该所有者可以按照智能体的常规工具策略进行协同咨询。所有者可以使用针对相同微信对端和通道账号的绑定会话。其他被允许的参与者则在独立会话中获得只读咨询权限。请单独将呼入者添加到 `inboundAllowFrom` 中。

协同咨询的运行方式与智能体的普通聊天轮次相同。它们使用智能体所配置的模型（包括 `claude-cli` 等 CLI 运行时）及其回退模型。

:::note[使用提示]
未启用的通话类型将直接被忽略，既不主动接听也不主动拒绝。开启视频权限并不代表具备视频通话能力：即使设置 `video.enabled: true`，当前后端也无法处理视频画面，亦无法将其自动转为语音。

语音桥接器在等待呼叫方说话时发送静音数据。对于实时模型，如果呼叫方打断回复，桥接器会清空已排队的音频，并向语音模型上报预估的播放位置。GPT-Live 模型则自主处理打断。无论采用哪种方式，语音智能体都可以在 OpenClaw 智能体进行协同咨询的同时继续与呼叫方对话。
该适配器不会录制通话音频。协同咨询记录以及智能体在通话结束后总结的转录内容在开启会话持久化时会保存在 OpenClaw 中；适配器本身仅保留简短的通话摘要。其他提供商适配器若预检失败将报错退出，不会自动静默降级。
:::
