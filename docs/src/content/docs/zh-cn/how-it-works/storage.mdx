```text
~/.config/agent-wechat/
├── server/config.toml              服务端配置 (可选)
└── client.toml                     CLI 客户端：已保存的服务器列表与默认账号
~/.local/share/agent-wechat/        数据目录
├── api-token                       管理员所有者 API 访问令牌
└── accounts/<id>/
    ├── profile/                    微信 Profile：聊天记录、联系人、媒体文件
    └── agent/
        ├── control.sqlite          登录凭据、任务、事件日志
        └── media/                  加密的附件与上传文件
$TMPDIR                             离线检查用的临时只读快照
```

在 Windows 上，配置文件位于 `%APPDATA%\agent-wechat`，数据文件位于 `%LOCALAPPDATA%\agent-wechat`。macOS 采用与 Linux 一致的路径标准。

如果你是通过 `--official` 登录的，则不会生成 `profile/` 文件夹：Daemon 会直接使用 Linux 版微信所在的 `~/xwechat_files` 与 `~/.xwechat`（位于它们原本的位置），数据目录中只保留 Daemon 自己的文件。

## 附件存放位置 \{#where-attachments-are-kept}

| 附件 | 存放位置 |
| --- | --- |
| 图片、文件、视频和语音消息 | 仅保存在微信 Profile 中，Daemon 从该处读取。 |
| 表情、链接缩略图，以及引用消息中的图片和表情 | `agent/media/`，每个文件单独加密。Profile 中没有对应的位置。 |
| 待发送的文件 | `agent/media/`，直到使用它们的所有发送任务完成后一天。 |

如果删除了附件的文件，获取该附件时将返回 `media_not_cached`。Daemon 不会自行重新下载。

## control.sqlite 如何保持精简 \{#how-controlsqlite-stays-small}

`control.sqlite` 只保存进行中的工作，而不保存历史记录：排队中的发送、等待写入 Profile 的同步批次，以及用于防止请求重复执行的收据。Daemon 在启动时清理一次，之后每小时清理一次。清理只会删除 Daemon 已经持有的字节数据，绝不会发送、下载或修改 Profile。

| 记录 | 完整保留的条件 | 之后 |
| --- | --- | --- |
| 收到的消息批次 | 等待中，或属于最新的 256 批 | 仅保留批次 ID，保留 30 天 |
| 被阻塞的消息批次 | 属于最新的 256 批 | 仅保留尚未写入的命令，以及联系人记录 |
| 文字和媒体发送 | 未完成，或尚未写入 Profile，再加一天 | 保留简短收据，保留 90 天 |
| 表情任务（表情包、我的表情、发送、表情包下载） | 未完成，或尚未写入 Profile，再加一天 | 保留简短收据；每个表情包最新的 5 次下载会保留重新添加该表情包时复用文件所需的信息 |
| 语音消息音频 | 直到 Profile 中已有相同的音频为止 | 从 Profile 中读取 |
| 群聊和联系人变更、撤回 | 未完成，或尚未写入 Profile，再加一天 | 保留简短收据，保留 365 天 |
| 消息和事件的重复检查 | 30 天 | 删除 |
| 为排查问题保留的微信原始响应 | 7 天 | 删除 |
| 未下载过的附件（语音消息除外） | 7 天，或在下载排队期间 | 删除；重新列出该消息的媒体即可将其恢复 |

结果未知（`needs_review`）的请求会完整保留 7 天，或直到之后又累积了 100 条更新的记录。之后，发送和媒体任务保持 `needs_review`，群聊和联系人变更与撤回则变为 `expired`，错误码为 `review_expired`。无论哪种情况，都无法再自动修复。参见[发送与故障恢复](/how-it-works/sends/#how-long-a-key-works)。

释放的空间会归还给磁盘。要查看哪些内容占用了空间，请先停止 Daemon，然后运行：

```bash
wx store usage --account ID
```

该命令会列出文件大小、体积最大的数据表和 `runtime` 键组，以及清理程序必须保留的未完成工作。

## 备份 \{#back-up}

先停止 Daemon 服务（执行 `wx daemon stop`、`systemctl --user stop agent-wechat-native` 或 `docker compose stop`），然后打包备份数据目录：

```bash
tar -czf wechat-backup.tgz -C ~ .local/share/agent-wechat
```

使用 `--official` 时，请在该打包命令末尾追加 `xwechat_files .xwechat`。仅仅备份 Profile 目录会丢失在途发送记录、OpenClaw 处理位点以及撤回标记；仅仅备份数据目录则没有任何聊天历史记录。

## 修改数据路径 \{#change-locations}

可以在 `~/.config/agent-wechat/server/config.toml` 中配置 `dataDir`，或在启动命令中显式传递 `--data-dir` 参数。详见[配置选项](/reference/configuration/)。

<Aside title="使用提示">
- **运行中的 Daemon 直接读取它管理的 Profile。** 它复用只读数据库连接，并使用短时读事务。离线检查会创建数据库的私有副本（每个最多 2 GiB，总计最多 8 GiB），因此请确保 `$TMPDIR` 所在磁盘有足够的空间，切勿将其指向 Profile。
- **不会改动未知格式的 Profile。** Daemon 在写入前会检查每个数据库的结构，无法识别时即停止写入。请先备份并等待更新，不要强行写入。
- **损坏的数据库会被保留。** 如果 Daemon 自身的数据库未通过检查，它会保留原始文件，并在旁边保存一份恢复副本。
- **启动时可能留下临时副本。** 在打开需要升级或未正常关闭的数据库之前，Daemon 会先在该数据库旁边的 `.sqlite-admission-*` 文件夹中检查一份副本。如果检查期间 Daemon 被停止，该文件夹会一直保留，直到该数据库下次成功打开，之后才会被删除。
- **旧版数据目录会在启动后转换。** 早期版本把所有附件都存放在 `control.sqlite` 中。Daemon 会在后台将它们移出，删除没有任何记录引用的文件，然后缩小数据库。在完成之前，数据目录可能会短暂需要额外空间，用于存放 Profile 中没有的附件。
- **升级前请先备份。** 升级可能会改变数据目录的格式，旧版 `wx` 无法打开已被新版升级过的数据目录。此后，清理会永久删除 `control.sqlite` 中已完成的记录。如需回退到旧版本，请恢复你在升级前做的备份。
- **撤回标记保存在数据目录中。** 导出 Profile 时不会包含它们。
- **升级后首次清理可能需要一段时间。** 清理按小批进行，因此其他请求仍会继续运行。删除第一批大数据时，需要约为 `control.sqlite` 两倍大小的可用磁盘空间；空间不足时，剩余空间会稍后再回收。
- **被阻塞的同步批次会被保留。** 包含 Daemon 不支持的命令的批次会一直保留，直到更高版本能将其写入 Profile，而 Profile 保存的同步位置也会等待该批次。`wx store usage` 会将它们计入 `syncBatchesBlocked`，并在 `blockedControls` 下列出阻塞这些批次的状态和系统控制项。
- **`wx store usage` 会将数据目录升级** 到已安装版本的格式，与其他 `wx store` 命令一样。如果想保留原始文件，请在副本上运行。
- **`consumerStateDir`** 也需要一并备份，OpenClaw 将自己的处理进度保存在其中。从早期插件版本升级后，首次启动时会把该文件转换为新格式，并在旁边保留原文件，文件名以 `.v1-backup` 结尾。该备份仍包含消息正文，不再需要回退时请将其删除。旧版插件无法读取转换后的文件；若要回退，请恢复该备份，这样旧版插件会重新处理升级后收到的消息。
</Aside>
