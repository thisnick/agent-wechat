| 微信消息类型 | 本地 API 输出内容 | 在 OpenClaw 中的呈现 |
| --- | --- | --- |
| 文本 (Text) | `body` 字段 | 文本正文 |
| 图片 (Image) | 可下载的图片资源，自动取本地最高可用画质 | 以图片形式提供给模型 |
| 文件 (PDF、Word 等) | 可下载的二进制文件 | 附带的文件 |
| 视频 (Video) | 可下载的 MP4 视频 | 附带的视频 |
| 语音留言 (Voice) | 自动转码缓存的可播放音频 | 已配置时为转录文本；否则为附带的音频 |
| 动态表情 (Sticker) | 表情原始图片字节 | 图片 |
| 引用回复 (Quote) | `body` 为当前回复正文，同时内嵌引用原消息摘要 | 回复正文，并附带明确标识的引用片段 |
| 合并转发聊天记录 | 格式化好的对话发言者与内容清单 | 同样的文本 |
| 链接分享卡片 (文章、音乐、视频号) | 标题、摘要、跳转 URL、来源、可选缩略图 | 卡片格式化文字及缩略图 |
| 静态位置 (Static location) | `location` 坐标、附带的地名/地址与可读的 `body` | 位置文本内容 |
| 实时位置共享提示 (49/17) | 协议附带的标题文本 | 被动通知；不加入共享 |
| 纯文本系统通知 | 协议下发的系统文本（无消息作者） | 不触发新的智能体轮次 |
| 撤回通知 (Recalled) | `[Message recalled]` | 从待处理工作中移除 |
| 其他未知类型 | 标记为不受支持 (Unsupported) | 不投递给智能体 |

## 文本表情 (Text emoji) \{#text-emoji}

桌面端与 Web 端应用会将识别到的微信表情代号（例如 `[微笑]` 和 `[Lol]`）显示为 Unicode Emoji。部分表情采用近似等价的 Emoji 替代；具体外观取决于你的操作系统设备。桌面系统通知同样使用此映射规则。未知的表情别名与原有的 Unicode Emoji 保持不变，URL 链接保持其原始拼写。消息发送、复制、搜索以及 API 响应仍保留原始消息文本。

## 位置信息 (Locations) \{#locations}

静态位置消息暴露 `location.latitude`、`longitude`、可选的 `name`（地名）、`address`（地址）、`scale`（缩放比例）、`mapType` 和 `poiId`，以及可读的 `body`。坐标系统报告为 `unknown`；坐标不进行自动转换，也不会自动请求任何地图服务。桌面端应用显示一张位置卡片并提供两项 Google 地图操作：**“搜索地点” (Search place)** 将其地名/地址和共享坐标作为搜索上下文，而 **“查看大头针” (View pin)** 则直接打开共享的具体坐标。搜索结果不受严格边界限制。用户也可以直接复制坐标；系统不应用任何坐标系转换。OpenClaw 依然应用常规的发送者与群聊 @ 提醒规则。

实时位置共享提示仅展示发送者附带的标题，不会启动或加入实时位置追踪，也不会下载地图缩略图。

## 语音留言 (Voice Notes) \{#voice-notes}

`wx` Daemon 在收到新的语音留言后会自动在后台完成下载，并解码为标准可播放音频。即使没有保持打开桌面端或任何 OpenClaw 会话，该流程依然静默运行。下载任务依托标准媒体任务机制调度，在服务重启后会继续未完成的下载，并在账号掉线时暂停。被取消或失败的任务可以通过 Media API 查看状态，系统不会静默地重新提交。本地修复不会下载新的媒体。

## 引用回复 (Quotes) \{#quotes}

接收到的引用回复仅使用微信服务端协议下发的回复包中所携带的内容。通过 `GET /messages/{id}` 或常规消息查询接口拉取该回复：其 `body` 为本次回复的文本，`quote` 对象中包含被引用原消息的服务端 ID、发言人、消息类型、已解析文本以及多媒体资源可达性。针对被引用的文章、音乐与视频卡片，`quote.embeddedLink` 提供了与普通外链相同的标题、描述、跳转链接和来源等信息。OpenClaw 直接依据这些字段渲染文本和链接卡片详情。本地已存储的原消息绝不会替换引用中的摘要内容。本地撤回检查仍会屏蔽已撤回的内容。

当引用中提供了 `quote.senderName` 时，它为回复中携带的作者显示名称。

图片、受支持的表情包和链接缩略图可以依据引用中包含的元数据下载。桌面端与 Web 端能够以紧凑卡片或小缩略图的形式呈现引用内容；点击引用可快速跳转到原始消息。对于失效或过期的多媒体，引用旁会清晰呈现状态标记。对于被引用的语音、视频和文件，系统将保留评论文本与受支持的摘要，并标注附件不可用的状态；其实际附件不会从已存储的原消息中获取。

即使被引用的原消息未在本地完整存储，嵌入式的引用卡片依然可以正常显示。媒体拉取依托回复消息的 ID 进行。如果想要发出你自己的引用回复，请向标准发送接口提交本地存储的目标消息 ID 和服务端 ID。参考[发送引用回复](/use/cli/#quoted-replies)。

## 微信表情 (Shared Stickers) \{#shared-stickers}

普通表情（Type 47）与受支持的应用表情（Subtype 8）使用相同的下载与图片校验流程。动态原图保留动画效果。在原图下载完成前可优先显示缩略图；原图同样受账号的自动下载阈值限制。格式未知或采用专有加密的表情保持不可用。

## 合并转发聊天记录 \{#forwarded-chats}

合并转发的消息合集会被转换为纯文本：逐行呈现每一位发言者及其发言内容，嵌套的聊天记录以缩进区分。合集内的图片与文件仅以占位文本呈现，不会下载。

## 分享卡片 (Link Cards) \{#link-cards}

| 接收到的类型 | 展示形态与限制 |
| --- | --- |
| 普通分享文本 (Subtype 1) | 纯文本；完整的 HTTP(S) URL 保持可点击跳转。 |
| 视频号卡片 (Channels 51) | 标题、描述、作者名与外链；不直接播放视频号视频。 |
| 文件上传通知 (74) | 文件名提示；不保证实际传输进度或最终可用性。不会触发 OpenClaw 推理。 |
| 群公告 (87) | 纯文本形式展示公告正文。 |

分享文本、视频号卡片与群公告均支持被引用和撤回。上传通知的引用内容可以正常查看，但上传通知本身不能作为被引用的目标消息。引用预览使用回复中携带的文本。

你可以使用 `wx messages send --share URL --title ...` 或通过 `wechat_send_share` 工具发送分享卡片。只需提供标题、描述与缩略图外链，系统不会从页面抓取任何内容。

## 消息撤回 (Recalls) \{#recalls}

当会话中有人撤回消息时，Daemon 会将本地数据库中该记录的正文替换为撤回提示，但完整保留其消息 ID 及时间轴位置。该消息的多媒体附件将无法再获取（返回 HTTP 410），即使本地已有缓存。你可以使用 `wx messages recall` 或 `wechat_recall` 工具撤回你自己发出的消息；是否仍可撤回由微信决定。

API 中将该消息的 `body` 保持为 `[Message recalled]`，并在已保存的通知可用时从中读取 `recall.replacementText`。它直接从原记录或已有的同步与发送回执中推导原始消息的 `senderId` 与 `direction`，无需额外存储第二份作者信息。若证据缺失或存在冲突，相关字段置为 `null`。撤回事件会指明受影响的消息 ID，重新拉取即可获得最新详情。

对于支持的官方全文检索索引，撤回操作还会同步清除对应的搜索词条。无关条目保持不动。若遇到不熟悉的索引结构，本地清理将保持待处理状态，等待检查。

<Aside title="使用提示">
- **附件以文件形式传给 OpenClaw，而不是以路径写入消息文本。** OpenClaw 会将附件列给智能体，并把文件复制到沙箱智能体的工作区（OpenClaw 会复制不超过 50 MB 的文件）。
- **部分图片使用微信特有的 WXGF 格式。** 系统会保留原始文件，并使用 FFmpeg 额外生成一张静态 JPEG 便于查看。静态预览不包含动图帧。
- **原始 XML 绝不会作为消息内容或附件返回。**
- **撤回并不能消除所有痕迹。** 已缓存的文件、备份以及智能体已读取的内容仍然保留。这并非安全擦除。
- 发送分享卡片与卡片缩略图为新特性，对方手机端的呈现效果仍需进一步在真机上验证。
</Aside>
