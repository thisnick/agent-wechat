| 微信消息 | 你获得的内容 | 在 OpenClaw 中 |
| --- | --- | --- |
| 文本 | `body` | 消息文本 |
| 图片 | 可下载的图片，取可用的最高画质 | 展示给模型 |
| 文件（PDF 等） | 可下载的文件 | 作为附件的文件 |
| 视频 | 可下载的 MP4 | 作为附件的视频 |
| 语音 | 自动缓存的音频 | 若已配置则为转录文本；否则为附件音频 |
| 动态表情 | 表情的原始字节 | 图片 |
| 引用回复 | `body` 中为评论，并附带回复中内嵌的被引用内容 | 评论和带标签的引用内容 |
| 合并转发聊天记录 | 可读的发言人与内容列表 | 同样的文本 |
| 链接卡片（文章、音乐、视频） | 标题、描述、URL、来源、可选缩略图 | 卡片文字和缩略图 |
| 静态位置 | `location` 坐标、附带的地名/地址，以及可读的 `body` | 位置文本 |
| 位置共享通知（49/17） | 附带的标题文字 | 被动通知；不会加入共享 |
| 普通系统通知 | 附带的文字，无消息作者 | 不会开启新的智能体轮次 |
| 已撤回的消息 | `[Message recalled]` | 从待处理工作中移除 |
| 其他 | 标记为不支持 | 不发送给智能体 |

## 文本表情 \{#text-emoji}

桌面端和 Web 端应用会把识别到的微信表情代号（例如 `[微笑]` 和 `[Lol]`）显示为 Unicode 表情。部分表情使用近似的替代图案，具体外观取决于你的设备。桌面系统通知使用同样的映射规则。无法识别的代号和已有的 Unicode 表情保持不变，URL 的拼写也保持原样。发送、复制、搜索以及 API 响应仍保留原始消息文本。

## 位置信息 \{#locations}

静态位置消息提供 `location.latitude`、`longitude`，以及可选的 `name`、`address`、`scale`、`mapType` 和 `poiId`，并附带可读的 `body`。坐标系统报告为 `unknown`；坐标不会被转换，也不会自动请求任何地图服务。桌面应用会显示一张位置卡片，提供两个 Google 地图操作：**搜索地点（Search place）** 会把地名/地址和分享的坐标作为搜索上下文，**查看标注（View pin）** 则直接打开分享的坐标。搜索结果不受严格的范围限制。你也可以复制坐标；不会进行任何坐标转换。OpenClaw 应用常规的发送者规则和群聊 @ 提醒规则。

位置共享通知只显示发送者提供的标题，不会开始或加入实时位置共享，也不会下载地图缩略图。

## 语音留言 \{#voice-notes}

`wx` 守护进程会自动下载新收到的语音留言，并准备好可播放的音频。这一过程不需要打开浏览器或 OpenClaw 会话。下载使用常规的媒体任务，守护进程重启后可以继续，账号断开连接时会暂停。已取消或失败的任务可以通过媒体 API 查看；系统不会悄悄重新提交。本地修复不会下载新的媒体。

## 引用 \{#quotes}

收到的引用只使用微信服务器协议随回复一起送达的内容。通过 `GET /messages/{id}` 或常规的消息列表接口读取回复：其 `body` 为当前的评论，`quote` 包含被引用消息的服务端 ID、发送者、类型、解析后的文本以及媒体可用性。被引用的文章、音乐和视频卡片还会在 `quote.embeddedLink` 中提供与普通链接相同的标题、描述、URL 和来源字段。OpenClaw 直接从这些字段渲染文字和链接卡片的详情。本地保存的原始消息绝不会替换引用中的摘要。本地撤回检查仍会屏蔽已撤回的内容。

提供 `quote.senderName` 时，它是回复中携带的作者显示名称。

图片、受支持的表情和链接缩略图可以使用引用中内嵌的元数据下载。桌面端和 Web 端以紧凑的卡片或小图预览的形式显示引用；点击引用可跳转到对应消息。缺失或过期的媒体会在评论旁以状态形式保留。被引用的语音、视频和文件会保留评论和受支持的摘要，附件显示为不可用；其实际附件不会从本地保存的原始消息中获取。

即使被引用的原始消息没有保存在本地，嵌入的引用也能显示。媒体获取使用父级回复的 ID。要发送你自己的引用回复，请使用普通的发送接口，并填入已保存目标消息的消息 ID 和服务端 ID。参见[发送引用回复](/use/cli/#quoted-replies)。

## 分享的表情 \{#shared-stickers}

普通表情（类型 47）和受支持的分享表情（应用子类型 8）使用相同的下载和图片校验流程。动态原图会保留动画效果。原图下载期间可以先显示缩略图；原图遵循账号的自动下载限制。来源或加密方式不受支持的表情仍不可用。

## 合并转发的聊天记录 \{#forwarded-chats}

合并转发的聊天记录会转换为纯文本：每位发言人和每条消息各占一行，嵌套的记录会缩进显示。记录中的图片和文件只显示为占位文字，不会被下载。

## 链接卡片 \{#link-cards}

| 收到的类型 | 显示方式和限制 |
| --- | --- |
| 分享的文本（子类型 1） | 纯文本；完整的 HTTP(S) URL 可点击。 |
| 微信视频号（51） | 标题、描述、作者和提供的链接；不播放视频号视频。 |
| 文件上传通知（74） | 文件名提示；不说明当前进度或最终是否可用。不会触发 OpenClaw 模型处理。 |
| 群公告（87） | 纯文本形式的公告内容。 |

分享的文本、视频号卡片和群公告都可以被引用和撤回。收到的文件上传通知的引用可以显示，但上传通知本身不能被选作回复的目标。引用预览使用回复中携带的文字。

你可以使用 `wx messages send --share URL --title ...` 或 `wechat_send_share` 工具发送分享卡片。你需要提供标题、描述和缩略图 URL；系统不会从页面抓取任何内容。

## 撤回 \{#recalls}

有人撤回消息时，守护进程会把该消息保存的正文替换为撤回通知，同时保留消息 ID 和在时间线中的位置。即使本地已有缓存，其媒体也无法再获取（HTTP 410）。你可以使用 `wx messages recall` 或 `wechat_recall` 工具撤回自己发出的消息；是否仍可撤回由微信服务器决定。

API 会将 `body` 保持为 `[Message recalled]`，并在保存的通知中有 `recall.replacementText` 时读取它。原消息的 `senderId` 和 `direction` 来自原始记录，或已有的同步和发送成功回执，系统不会额外保存第二份作者信息。证据缺失或互相冲突时，这些字段为 `null`。撤回事件会指明受影响的消息；如需最新详情，请重新获取该消息。

对于支持的官方全文搜索索引，撤回还会删除原消息的条目及其搜索词。其他条目保持不变。遇到不认识的索引结构时，本地清理会保持待处理状态，等待检查。

<Aside title="使用提示">
- **附件以文件的形式传给 OpenClaw，而不是以路径的形式出现在消息文字中。** OpenClaw 会把附件列给智能体，并复制到沙箱智能体的工作区（复制上限为 50 MB）。
- **部分图片使用微信的 WXGF 格式。** 系统会保留原文件，并用 FFmpeg 生成一张 JPEG 静态图供查看。静态图不包含动画帧。
- **原始 XML 绝不会**作为消息内容或附件返回。
- **撤回不会清除所有内容。** 已缓存的文件、备份以及智能体已经读取过的内容仍会保留。这不是安全删除。
- 分享卡片的发送和缩略图是新功能，尚未确认收件人手机上的显示效果。
</Aside>
