| 微信消息类型 | 本地 API 输出内容 | 在 OpenClaw 中的呈现 |
| --- | --- | --- |
| 文本 (Text) | `body` 字段 | 文本正文 |
| 图片 (Image) | 可下载的图片资源，自动取本地最高可用画质 | 多模态呈现给大模型视窗 |
| 文件 (PDF、Word 等) | 可下载的二进制文件 | 对应的本地文件路径 |
| 视频 (Video) | 可下载的 MP4 视频 | 对应的本地文件路径 |
| 语音留言 (Voice) | 自动转码缓存的可播放音频 | 音频文件路径，若配置了语音识别则附带转录文本 |
| 动态表情 (Sticker) | 表情原始图片字节 | 静态或动图展示 |
| 引用回复 (Quote) | `body` 为当前回复正文，同时内嵌引用原消息摘要 | 回复正文，并附带明确标识的引用片段 |
| 合并转发聊天记录 | 格式化好的对话发言者与内容清单 | 纯文本展示 |
| 链接分享卡片 (文章、音乐、视频号) | 标题、摘要、跳转 URL、来源、可选缩略图 | 卡片格式化文字及缩略图 |
| 静态位置 (Static location) | `location` 坐标、附带的地名/地址与可读的 `body` | 位置文本内容 |
| 实时位置共享提示 (49/17) | 协议附带的标题文本 | 被动通知；不加入共享 |
| 纯文本系统通知 | 协议下发的系统文本（无消息作者） | 不触发新的智能体轮次 |
| 撤回通知 (Recalled) | `[Message recalled]` | 从进行中的工作流中撤出消除 |
| 其他未知类型 | 标记为不受支持 (Unsupported) | 不投递给智能体 |

## 文本表情 (Text emoji)

桌面端与 Web 端应用会将识别到的微信表情代号（例如 `[微笑]` 和 `[Lol]`）显示为 Unicode Emoji。部分表情采用近似等价的 Emoji 替代；具体外观取决于你的操作系统设备。桌面系统通知同样使用此映射规则。未知的表情别名与原有的 Unicode Emoji 保持不变，URL 链接保持其原始拼写。消息发送、复制、搜索以及 API 响应仍严格保留原始消息文本。

## 位置信息 (Locations)

静态位置消息暴露 `location.latitude`、`longitude`、可选的 `name`（地名）、`address`（地址）、`scale`（缩放比例）、`mapType` 和 `poiId`，以及可读的 `body`。坐标系统报告为 `unknown`；坐标不进行自动转换，也不会自动请求任何地图服务。桌面端应用显示一张位置卡片并提供两项 Google 地图操作：**“搜索地点” (Search place)** 将其地名/地址和共享坐标作为搜索上下文，而 **“查看大头针” (View pin)** 则直接打开共享的具体坐标。搜索结果不受严格边界限制。用户也可以直接复制坐标；系统不应用任何坐标系转换。OpenClaw 依然应用常规的发送者白名单与群聊 @ 提醒过滤规则。

实时位置共享提示仅展示发送者附带的标题，不会启动或加入实时位置追踪，也不会下载地图缩略图。

## 语音留言 (Voice Notes)

`wx` Daemon 在收到新的语音留言后会自动在后台完成下载并解码为标准可播放音频。即使没有保持打开桌面端或任何 OpenClaw 会话，该自动化流程依然静默运行。下载任务依托标准媒体任务机制调度，在服务重启后支持断点续传，并在账号掉线时挂起等待。被取消或失败的任务可以通过 Media API 进行状态排查，系统绝不会静默无底线地盲目反复发起重试。本地数据校验修复同样绝不产生无谓的网络请求。

## 引用回复 (Quotes)

接收到的引用回复严格仅提取微信服务端协议下发的回复包中所内嵌的引用摘要。通过 `GET /messages/{id}` 或常规消息查询接口拉取详情：其 `body` 为本次回复的文本，`quote` 对象中包含被引用原消息的服务端 ID、发言人、消息类型、已解析文本以及多媒体资源可达性。针对被引用的文章、音乐与视频卡片，`quote.embeddedLink` 提供了与普通外链相同的标题、描述、跳转链接和来源等信息。OpenClaw 可直接据此渲染出详尽的上下文引用。本地已有存储的被引用原消息绝不会覆盖协议中自带的原汁原味的引用摘要。若原消息被撤回，引用处的内容同样会被依法屏蔽。

图片、受支持的表情包和链接缩略图可以直接依据引用中包含的元数据完成下载。桌面端与 Web 端能够以紧凑卡片或小缩略图的形式呈现引用内容；点击引用可快速定位跳转到原始消息。对于失效或过期的多媒体，引用旁会清晰呈现状态标记。对于被引用的语音、视频和文件，系统将保留文本回复与摘要文本，并标注附件处于不可用状态，绝不会擅自从本地数据库深处逆向提取其完整原始大文件。

即使被引用的原消息未在本地完整存储，嵌入式的引用卡片依然可以正常渲染显示。媒体拉取依托父级回复消息的 ID 展开。如果想要发出你自己的引用回复，请向标准发送接口提交本地存储的目标消息 ID 和服务端 ID。参考[发送引用回复](/zh-cn/use/cli/#引用回复)。

## 微信表情 (Shared Stickers)

普通表情（Type 47）与受支持的应用表情（Subtype 8）共用相同的下载与图片校验逻辑。动态表情完整保留其动图帧率。在原图下载完成前可优先显示缩略图；原图下载受账号的自动下载阈值限制。格式未知或采用专有加密的表情保持不可用。

## 合并转发聊天记录

合并转发的消息合集会被解构成层次清晰的纯文本结构：逐行呈现每一位发言者及其发言内容，嵌套的聊天记录以缩进清晰区分。合集包内部包含的图片与文件仅以占位文本呈现，不主动执行递归全量下载。

## 分享卡片 (Link Cards)

| 接收到的类型 | 展示形态与限制 |
| --- | --- |
| 普通分享文本 (Subtype 1) | 纯文本；完整的 HTTP(S) URL 保持可点击跳转。 |
| 视频号卡片 (Channels 51) | 标题、描述、作者名与外链；不直接播放视频号流媒体。 |
| 文件上传通知 (74) | 文件名提示；不保证实际传输进度或最终可用性。不会触发 OpenClaw 推理。 |
| 群公告 (87) | 纯文本形式展示公告正文。 |

分享文本、视频号卡片与群公告均支持被引用和撤回。上传通知的引用内容可以正常查看，但上传通知本身不能作为被引用的目标消息。

你可以使用 `wx messages send --share URL --title ...` 或通过 `wechat_send_share` 工具外发分享卡片。只需提供标题、描述与缩略图外链，系统不会擅自发起网络抓取。

## 消息撤回 (Recalls)

当会话中有人撤回消息时，Daemon 会将本地数据库中该记录的正文替换为撤回提示，但完整保留其消息 ID 及时间轴位置。该消息包含的多媒体附件将永久被屏蔽（返回 HTTP 410），即便利器本地已存在缓存。你可以使用 `wx messages recall` 或 `wechat_recall` 工具撤回你自己发出的消息；微信服务端会裁定该消息是否仍在允许撤回的时间窗口内。

API 中将该消息的 `body` 维护为 `[Message recalled]`，并在协议可用时从通知中读取 `recall.replacementText`。它直接从原记录或已有的同步/发送收据中推导原始消息的 `senderId` 与 `direction`，无需额外冗余持久化第二份作者信息。若证据缺失或存在冲突，相关字段置为 `null`。撤回事件会指明受影响的消息 ID，重新拉取即可获得最新状态。

对于支持的官方全文检索索引，撤回操作还会同步清除对应的搜索词条。无关索引保持不动。若遇到不熟悉的索引结构，本地清理将置为挂起待查状态。

<Aside title="使用提示">
- **部分图片使用微信特有的 WXGF 格式。** 系统在保存原始文件的同时，会使用 FFmpeg 额外提取一张静态 JPEG 便于快速查看。静态预览不包含动图帧。
- **绝不直接向业务层返回未解析的原始 XML。**
- **撤回并不能消除所有痕迹。** 已落盘的本地文件、备份数据以及已被智能体读入上下文的记忆依然存在。它不属于不可逆的绝密销毁。
- 发送分享卡片与卡片缩略图为新特性，对方手机端的呈现效果仍需持续真机验证。
</Aside>
