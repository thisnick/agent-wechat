---
title: Tokens and Authentication
description: API access and native WeChat authorization have separate lifetimes.
---

The API bearer token controls access to the daemon; WeChat active/saved credentials authorize native protocol exchanges. Rotating one does not refresh or revoke the other. Default daemon initialization creates owner-only token/key files under `dataDir`; a `tokenFile` setting can instead reference an explicitly provisioned private file. Keep tokens out of URLs and source control.

The CLI accepts `--token-file` and endpoint-scoped configuration. OpenClaw requires an absolute regular mode-0600 token file with at least 32 bytes on one line. Remote API access requires verified HTTPS or an authenticated encrypted tunnel to loopback.

```bash
wx tokens create integration --accounts ACCOUNT_ID --scopes read
wx tokens list
wx tokens revoke TOKEN_ID
```

Available scopes are `read`, `media`, `send`, `read-state`, `login` and `admin`. Grant only the selected accounts/scopes. OpenClaw uses read/media/send/login, plus read-state when automatic local reads are wanted; normal operation does not need admin. The optional Gateway facade uses the Gateway's own authentication and a separate daemon token reference.

Stopping/disconnecting keeps reusable WeChat trust. Explicit native logout commits a persistent local fence and makes at most one authenticated logout exchange without renewing merely to log out. Saved-device trust revocation is not established. Explicit local forgetting is separately confirmed and retains history/media; neither action deletes backups or proves removal from the phone's device list.
