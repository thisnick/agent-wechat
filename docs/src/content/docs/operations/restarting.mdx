---
title: Restarting and Recovery
description: Preserve login trust, durable work and profile ownership.
---

Use the same process owner to stop and restart the native daemon. `wx daemon stop` terminates only the verified process it owns; systemd, Compose and OpenClaw managed mode have their own owners. A normal stop/disconnect retains reusable saved credentials and history. Never run two writers over the same official profile.

On restart, accepted credential generations, logout epochs, staged sync commands, projection journals, outgoing intents/jobs and consumer cursors are recovered separately. Background connection can validate or renew eligible authorization; it does not create a QR silently. Use an explicit login when phone approval/QR is needed.

A lost send response may mean WeChat accepted it. Keep the idempotency key and submission receipt, inspect the existing send/job, and never resend `needs_review` work automatically. Partial voice jobs retain each completed note ID. HTTP or Gateway disconnect does not cancel server-owned durable work.

```bash
wx --account ACCOUNT_ID messages sends lookup --idempotency-key EXISTING_KEY
wx --account ACCOUNT_ID jobs get JOB_ID
wx --account ACCOUNT_ID jobs repair-writeback --limit 25 --wait 30
```

Local writeback repair reconciles owned bytes/accepted receipts into supported official files and never submits another network transfer or message. Unknown layouts remain blocked. Preserve profiles and sidecars before diagnosis; deleting files to force a fresh login can lose device trust, database keys or pending receipts.
